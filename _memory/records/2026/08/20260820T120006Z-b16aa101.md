## Problem

After v0.12.0 dispatch, completion behavior was still single-slot shaped: CB1/CB2 stopped the whole run, drained backlogs could exit 0 while quarantined branches remained, the exit-code block still described sentinel-based completion, and quarantine left no durable artifact.

## Outcome

Shipped kit **v0.13.0** in commit **f9bfb3d**: slot **retirement** replaces run-fatal CB1/CB2 exits at the tripping reap; single **`_loop_aggregate_exit`** funnel implements precedence **4>3>2>1>0**; drained completion exits 0 only with zero quarantined branches (else exit 1 with P4 banner); quarantine **marker files** under `.loop-worktrees/` with embedded dispatch prompts on failure paths; dispatch-prompt capture in outbox; PowerShell `$status` normalization; check G extended to exits 0–5 plus kitVersion==VERSION tripwire in check J; harness 111 assertions; design doc §7 marked shipped with ratified deviations.

## Key decisions

- Ratify sentinel-as-mismatch under driver dispatch; implement exit-0 gating on quarantined branches (D1).
- Marker at `.loop-worktrees/QUARANTINE-<branch>.md` instead of in-worktree paths (accepts loss of uncommitted dirty worktree state; records `dirty_paths`).
- Fifth exit-5 site: loud stop when backlog readable at last fill but missing/unreadable at funnel completion with dispatches already made.
- No instance re-emit of `_loop/` in this story (canonical templates only; instance lag routed to a future instance-granted story).

## Pitfalls / lessons

- Two-gate aggregation leaked lying exit 0/1 when retirement coincided with MAX_ITER exhaustion—funnel required.
- Patch-mode staging needed when parallel goals edited the same template files after task judgment.
- `_loop_backlog_set_field` unguarded write on missing backlog remains a pre-existing gap routed to backlog.
