The loop harness verbatim-extracts functions and anchored lines from canonical and `_loop` drivers for live behavioral tests. Refactoring variable names, reordering functions, or moving guarded blocks without an upfront identifier-preservation pin in the goal plan surfaces failures only at the EMIT task — which cannot legally rewrite harness-owned anchors.

Pin preserved identifiers (function names, coupled guard blocks, literal exit tokens) in the restructuring task's acceptance criteria before touching `loop.sh` / `loop.ps1`.
