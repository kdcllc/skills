When one task's acceptance criteria require another task's emitted text to match exactly — for example check K's replication of goal-criteria clauses — those tasks cannot run in parallel without weakening the check. STORY-007 paid that cost as task 02 before task 01 serialization (`02→01`), keeping an unweakened K(c) mutation proof.

The strongest producer-to-consumer handoff is spec-equals-anchor: the normative requirement wording **is** the literal the producer must emit, so compliance forces the consumer's anchor text to appear unchanged.

Context: STORY-007 (story-007-check-j, kit v0.9.0)
