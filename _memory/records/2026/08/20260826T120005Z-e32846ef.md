**Intent**: Understand how the kit generates contracts.md-style artifacts during feature work.

**Decisions**: None required from the user; this was an explanatory question. The assistant clarified there is no single contracts.md file—artifacts are per-task contract files under the goal contracts directory, named with task ordinal and slug.

**Outcome**: Explained the Phase 4 contract gate: the task owner (implementer or test-writer) proposes a contract from the template, expanding requirements into acceptance criteria with explicit verification methods; evaluator reviews in contract mode with at most two revision rounds; implementation does not start until both worker and evaluator sign off. Contracts become the frozen verification standard for implementation, fix cycles, and evaluator arbitration. Pointed to the feature skill template and a live goal example for shape.

**Open threads**: None from the session. The separate pre-code contract gate described here was removed later the same day in kit v0.23.0; task files now carry acceptance criteria instead.
