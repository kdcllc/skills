## Problem

The model circuit breaker persisted state with a non-atomic truncate-then-write, so a reader could catch a torn file, mis-parse it, and reseed to CLOSED—silently clearing an OPEN cooldown during rate limiting. Routed loop-twin fixes also closed parity gaps: exit-code contract omitted 126/127, and bash prompt reads diverged from PowerShell on CRLF tails.

## Outcome

Shipped kit **v0.10.0** in commit **41d1359**: atomic temp-plus-rename writes in bash and PowerShell breaker twins; CR-tolerant terminator check; three-branch load with torn-read retries then fail-safe OPEN (preserving parsed chain/index/currentModel semantics); loop twins updated for 126/127 documentation and iterative trailing CR/LF stripping; loop harness expanded (45 assertions green); design and README aligned.

## Key decisions

- Fail-safe inversion: unreadable state after retries seeds OPEN with full cooldown instead of fresh CLOSED.
- Optional `now` parameter on `breaker_load` at the API boundary for testability without violating no-wall-clock header rules.
- Check G left unchanged; new PowerShell mechanics guarded via harness structural assertions (precedent of assertions 18/19).
- Contract-breaking harness updates owned in-pack (assertions 11/11b).

## Pitfalls / lessons

- CR-only trailing strip fails on tails like `text\r\n\r\n`; both `\r` and `\n` must be stripped iteratively for TrimEnd parity.
- Harness assertion 31 needed timing fixes so retry-recovery was deterministically tested, not coin-flip.
- Mutation-proof grep for exit 127 must anchor on the guard line, not the first textual match (decoy in comments).
