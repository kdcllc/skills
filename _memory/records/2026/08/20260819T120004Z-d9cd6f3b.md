## Decision

Prevent multi-feature write collisions at planning time via per-task ownership blocks (`writes`, `reads`, `depends_on`, `owner`, `rewrite_semantics`), judge-verified disjointness and coverage, and worker fail-loud fences—instead of relying on branch isolation and merge repair.

## Why

Research and AgenticFlict data favor declared disjoint write-sets over after-the-fact reconciliation. design-parallel-dispatch section 6.1 already adopts write-set admission as the planning layer; this story implements that half without changing loop drivers.

## Rejected alternatives

- Merge-time worktree isolation as primary strategy (contradicts prevention thesis; driver scope is later stories).
- Prose-only file lists in task templates (status quo, no machine verification).

## Consequences

Orchestrator logs must record writes claims; implementers escalate on out-of-fence needs. STORY-011 adds driver admission; check K guards canonical template shape.
