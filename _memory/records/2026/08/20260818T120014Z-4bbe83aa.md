## Decision

Implement Windows loop support as a full PowerShell 7+ `loop.ps1` that duplicates breaker and driver logic, declared behaviorally identical to `loop.sh`, rather than a thin shim launching bash or a shared Node implementation.

## Why

Zero new runtime dependencies and idiomatic pwsh on pure-Windows machines. A shim fails without git-bash/WSL; Node couples the one script that must run when tooling is broken.

## Rejected alternatives

- Single Node driver (rejected: new dependency in critical path).
- ~15-line pwsh launcher execing `loop.sh` (strongest rejected alternative—documented for revisit if parity drift appears).

## Consequences

Parity relies on headers, checks, and harness heuristics; any divergence is treated as a bug. Future breaker and dispatch features must land in both twins unless a later story revisits the launcher approach.
