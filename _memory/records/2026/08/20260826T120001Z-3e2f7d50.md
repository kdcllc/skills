## Decision

Emit one forge-aware `ship-pr` skill for all installs. At invocation it classifies the forge from git remote URLs (precedence: upstream → forge-named → origin), honors `options.forge` / `options.forgeHost` in `orchestration-kit.manifest.json`, and branches to GitHub, Azure DevOps, GitLab, or a `none` hand-over path. Setup records detection on first run and re-detects on upgrade. **Never write git config** to store overrides.

## Why

Emit-time forge variants would multiply templates and reintroduce fan-out; runtime detection keeps canonical templates project-agnostic with zero new placeholders.

## Rejected alternatives

- Instructing users to delete Phase 7 on non-GitHub installs (removed — caused 14-site inconsistency).
- REST fallback for on-prem Azure DevOps Server (deferred — hand-over covers it).

## Consequences

All Phase 7 references stay valid on every forge. The `none` branch must be provably incapable of creating a PR (draft, optional push with approval, print URL/command only). GitHub path remains a regression guard for behavior parity with pre-v0.22.0.
