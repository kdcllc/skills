## Problem

The canonical loop driver was bash-only, so Windows users could install the kit but not run the autonomous loop natively. Setup lacked conditional guidance for project-adopted structural checks on PowerShell.

## Outcome

Shipped STORY-005 via supervised goal windows-support (closed 2026-08-18). Delivered `loop.ps1` as a behavioral twin of `loop.sh` (defaults, sentinel, three circuit breakers, exit codes 0–4), Windows template rules, all four emitters referencing both drivers, skip-aware pwsh verify in setup SKILL, and extended `.claude/checks.sh` (parse skip, parity heuristic). Kit VERSION and manifest bumped to 0.5.0; root docs updated in Phase 6. Phase 7 ship-pr skipped until repo publish (STORY-003). Six audit advisories routed to STORY-006 for polish.

## Key decisions

- Full behavioral twin chosen over Node unified driver or bash-launcher shim (pure pwsh box requirement).
- Always emit both drivers; no OS-detection branching in emitters.
- PowerShell 7+ (`pwsh`) only; no Windows PowerShell 5.1 shims.
- pwsh syntax validation skip-aware when pwsh absent on dev machine.

## Pitfalls / lessons

- False premise blocker: kit does not emit instance checks scripts—guidance must be conditional on adoption.
- Instance `.claude/` ORCHESTRATION staleness deliberately deferred to next `/setup` re-emit (hash-unmodified paths).
- Parity is heuristic, not proof—ongoing harness and check G guard drift.
