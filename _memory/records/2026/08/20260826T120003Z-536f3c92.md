## Decision

Fold the two-party contract gate into planning: each task file carries an `## Acceptance Criteria` section (criterion + verification method) created in Phase 2; the Phase 3 goal evaluator validates them once. Remove Phase 4 contract mode, the `contracts/` folder pattern, and `templates/skills/feature/templates/contract.md`. Keep ownership-contract blocks (`writes`, `reads`, `depends_on`, `owner`, `rewrite_semantics`, `eval_depth`) unchanged.

## Why

The contract gate added two spawns to every task (four minimum per task) and duplicated criteria already owned by goal/task evaluators — major token cost for little marginal safety after v0.18 eval hardening.

## Rejected alternatives

- Keeping contract sign-off alongside new acceptance sections (would double gate).
- Moving criteria skills to `reference/` globally (only feature ladder split was adopted).

## Consequences

Feature skill Phase 4 dispatches implementers directly after eval_depth routing. Historical `_goals/` contract artifacts remain archival only. Later ladder/arbitration docs must reference acceptance criteria in task files, not signed contract files. (Note: v0.18.0 had introduced contracts; v0.23.0 superseded that workflow.)
