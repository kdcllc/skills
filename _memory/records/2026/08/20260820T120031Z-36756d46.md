Standing backlog notes sometimes say attach a harness fixture when the next story touches a specific file (for example `tests/loop-harness/run.sh` chain fallback indexing). Routing those notes only inside the owning story's addenda misses tasks in **other** goals whose write-set includes the same path.

At goal-creation time, scan global backlog notes against **every** planned task's `writes:` fence — STORY-010 task 04 touched `run.sh` while a chain[`fallbackIndex`] fixture note remained unrouted because review was story-scoped only.
