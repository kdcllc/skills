## Problem

The setup skill assumed a brownfield repo with enough files to infer stack, tests, and layout. Empty or nearly empty directories had no guided path, so new projects could not bootstrap a sensible tree through `/setup`.

## Outcome

Shipped kit **v0.17.0** (release commit `eb6070a`). The setup compiler gained **Step 2a — Greenfield gate**: a sparse-directory heuristic (allowlist-only roots), always ask when sparse, print a recommended TypeScript/Node, Python, or generic tree, and **create nothing until the user explicitly confirms** that tree. Optional skills.sh installs (1000+ install floor, user pick, fail-open). Manifest `options.greenfield` drives a GREENFIELD-only BOOTSTRAP block in the emitted ORCHESTRATION template (engineering practices prose, docs-only). Non-sparse workspaces skip Step 2a entirely. Harness assertions 100–114 in `tests/loop-harness/run.sh` lock the contract.

## Key decisions

- Sparse means only allowlisted junk (`.git/`, licenses, empty dirs, etc.); any real project file skips the gate.
- Inference tokens (`{{FULL_TEST_COMMAND}}`, etc.) get explicit disposition: user values, `(not configured)`, or row deletion — never invented `npm test` / `pytest`.
- Stack-specific trees live in `skills/setup/SKILL.md`, not in project-agnostic templates.
- No emitter changes; no instance re-emit of agent/skill hashes beyond `kitVersion` join where allowed.

## Pitfalls / lessons

- TDD/SOLID guidance stays in emitted ORCHESTRATION docs only — not wired as auto-fail triggers (explicit discovery choice).
- Phase 7 commit/PR remained user-gated at goal close; kit release landed on master via the v0.17.0 bump commit.
