## Question

What should the kit adopt from Anthropic's 2025–26 harness-design line, especially renaming judge to evaluator?

## Load-bearing findings

- Anthropic lineage: orchestrator-workers and evaluator-optimizer (Dec 2024); multi-agent research read-heavy; long-running harness initializer + coding agent; Mar 2026 generator + evaluator with sprint contracts and live-app QA.
- Approved rename: `judge` → `evaluator`, `qa-judge` → `qa-evaluator` (kept separate); verdict tokens PASS / NEEDS FIXES / etc. unchanged; clean one-shot rename via `/setup` re-emit, no alias shims.
- Adopt: per-task contracts with two-party sign-off; execute-before-score evaluation; hard per-criterion thresholds; tier evaluation intensity via `eval_depth`, never skip gate; Copilot marks secondary evidence when browser MCP unavailable.
- Do not copy: one continuous SDK session as architecture, all-frontier workers, autonomous planner replacing Phase 1 alignment, optional per-task evaluation.

## Decisions taken

- Contract files at `contracts/NN-task-name.contract.md` sibling to tasks under goal dirs (superseded in kit v0.23.0 by task Acceptance Criteria sections).
- Task decomposition stays mandatory for write-set disjointness; only granularity may vary by model tier.
- Phase 4 fix-loop cap superseded for task execution by v0.20.0 continuation ladder (see autonomous-escalation research).

## Open questions

- Live QA, frontend-design skill routing, simplification policy ablation cycles planned as follow-on goals beyond phases 0–2.

## Where it shipped

Kit v0.18.0 phases 0–2: evaluator rename, evaluator hardening, contracts with eval_depth routing per doc status (promoted 2026-08-21).
