## Problem

After three implement→evaluate fix cycles, the feature flow always escalated to the human even though the kit had already rotated implementers across model families. Research showed strategy-changing continuation (diagnosis, criteria arbitration, decomposition) could succeed without burning human attention on low-yield fourth identical attempts.

## Outcome

Shipped kit **v0.20.0** (release commit `9d144c2`; feature branch commit `ac30f7b` merged with master). Phase 4 task execution now runs a **continuation ladder** (rungs 4–6: diagnostician report, evaluator arbitration against the signed contract, decomposition with selective retry) before terminal human escalation. New **`diagnostician`** agent (frontier, read-only report). Evaluator **arbitration mode** on a frontier different-family model token (not `{{MODEL_ALT_FAMILY}}`). Machine-readable failure-class tags; bypass classes (destructive ops, security-sensitive, production/infra) escalate immediately. Hard guards: ≤3 post-cycle-3 attempts, repeated identical required-fixes signature stops the ladder, every transition logged — no token/cost budgets claimed. `docs/research-autonomous-escalation.md` added; structural test `tests/templates/escalation-ladder.sh` extended. Loop drivers unchanged.

## Key decisions

- Adopt rungs 4–6; defer high-reasoning-effort pin and best-of-N (conflicts with disjoint write-set admission).
- Ladder applies to interactive feature Phase 4 and inherits in headless loop via phased flow — not to Phase 3/5/6 retry loops.
- Requirement ambiguity routes to arbitration, not automatic human bypass.

## Pitfalls / lessons

- Goal evaluation needed revision for write-set vs no-driver-changes and roster accounting before execution.
- `gh` OAuth identity mismatch blocked automated PR create; user opened PR manually after README merge conflict with parallel docs goal.
