## Problem

Story selection lived inside each loop iteration, so concurrent slots would pick the same backlog story and last-writer-win on `_goals/` files. STORY-010 shipped slot tables but guarded concurrency off. The design required driver-owned selection, write-set admission, and a single-writer integrator.

## Outcome

Shipped kit **v0.12.0** in commit **99145f3**: drivers parse backlog, admit on disjoint `writes:` globs and hotspot serialization, increment attempts at claim, pin `%%STORY_ID%%` and `%%OUTBOX_DIR%%` in per-slot prompts; dual-mode auto-loop skill (dispatched vs manual); integrator validates ITERATION lines, writes backlog transitions, merges outbox learnings/escalations; N>1 honored only when **LOOP_WORKTREE=1**; pre-merge rebase before ff-only integration; harness 82 assertions; canonical templates plus loop harness in commit (instance `_loop/` re-emitted in task 06).

## Key decisions

- Empty or absent `writes:` intersects everything → story runs alone; admission failures defer, protected-path intersection refuses dispatch loudly.
- Outboxes in driver mktemp dirs (not inside worktrees) for uniform flag=0/1 behavior.
- Compaction/archival of LEARNINGS deferred to manual skill runs; driver enforces size gates with loud stderr only.
- Sentinel in dispatched slot output treated as ITERATION mismatch, not completion.

## Pitfalls / lessons

- Harness red window expected from task 01 through 05 until sandboxes gained story blocks and banner literals updated.
- Parallel sessions repeatedly reverted VERSION or contaminated fenced files—close used selective staging and patch-mode blobs.
- kitVersion==VERSION join had no standing tripwire until STORY-012 added check J line.
