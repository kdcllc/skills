## Problem

The autonomous loop had iteration-level circuit breakers but no model-level resilience against provider rate limits. Rate-limited iterations could exhaust CB1 no-progress counting before any fallback model could help.

## Outcome

Shipped kit v0.6.0 (commit 8df2bbf). Added CLOSED/OPEN/HALF-OPEN breaker helper twins (`breaker.sh` / `breaker.ps1`), driver wiring with anchored rate-limit detection, fallback chain via `{{LOOP_MODEL_CHAIN}}`, and documentation in loop templates and ORCHESTRATION. Targeted tests and checks stayed green after SIGPIPE-related detection fixes.

## Key decisions

- State file at `_goals/breaker-state.json`, not under `_loop/` (CB0 protected); setup Step 5 appends gitignore guidance.
- Mechanism B for OPEN skips: sleep inside the iteration, then transition to HALF-OPEN and proceed without consuming an extra loop iteration conceptually.
- Single CB1 carve-out: rate-limit-detected passes increment a separate counter and do not bump `no_progress`.
- PowerShell twin writes identical flat one-key-per-line text, not `ConvertTo-Json`.
- Detection regex is anchored to reduce false positives on bare `429` or quota prose.

## Pitfalls / lessons

- Pipefail plus SIGPIPE on large captures caused false-negative rate-limit and sentinel detection; herestring-based grep fixes were required twice (stage-1 and stage-2).
- CRLF versus bash `$(cat)` parity on PROMPT handling surfaced early (later stories tightened guards).
- Vacuous parity check G can pass while headers still cite wrong canonical paths (addressed in story-006).
