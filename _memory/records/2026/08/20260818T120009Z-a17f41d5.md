## Decision

Define WIP-limited slot refill to trigger when a slot finishes (story iteration exits its driver slot), not when an external merge event occurs, adapting squad’s merge-gated formula because the kit loop does not push or merge pull requests itself.

## Why

The seed pattern `available-slots = max(0, 3 - active PRs)` assumes a forge integration the autonomous loop lacks. Refill-on-exit preserves bounded concurrency without inventing forge hooks in the design story.

## Rejected alternatives

- Literal transplant of PR-based slot accounting without adaptation (audit flagged as unjustified).
- Unbounded parallelism when backlog depth is high.

## Consequences

Implementation stories must track active slots in driver state, not CI merge status. Open questions remain for forge-aware Phase 7 delivery later.
