## Problem

Dual-harness installs (`.claude/` + `.cursor/`) let Cursor sessions resolve agents, skills, ORCHESTRATION, and model maps from `.claude/`, including stale bracket-param model IDs. Subagents could run on Claude-pinned models while the user expected Cursor-native paths only.

## Outcome

Shipped kit **v0.19.0** (release commit `f1bd48a`; dogfood commit `117630e` on master). Cursor emitter always emits skills, ORCHESTRATION.md, and `setup-models.map.md` under `.cursor/` with `{{IDE_DIR}}` → `.cursor`. Unconditional emit rows replaced reuse clauses. ORCHESTRATION template references the model map instead of inline `{{MODEL_*}}` pins. Setup documents per-emitter `{{IDE_DIR}}` and pre-v0.19.0 migration. New structural test `tests/templates/cursor-isolation.sh`. User chose direct-to-master commit (PR skipped). Accepted gap: loop `PROTECTED_PATHS` still `.claude`-only (backlog STORY-015).

## Key decisions

- Concrete Cursor model IDs live only in emitted instances, not canonical templates.
- Ignore-blind verification (`grep -rn` / `rg --no-ignore`) mandatory for gitignored instance trees.
- Copilot/Codex emitters unchanged this release.

## Pitfalls / lessons

- Live doc checks showed bracket params and slug-suffix IDs coexist — model map guidance must defer to emit-time verification, not one encoding scheme.
