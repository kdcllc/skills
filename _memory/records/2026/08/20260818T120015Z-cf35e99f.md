## Question

How to upgrade the kit so one template source serves Copilot, Cursor, Claude Code, and Codex with per-agent model pinning and an autonomous feature loop?

## Load-bearing findings

- `.claude/agents` and `.claude/skills` are de-facto interchange: Cursor and VS Code Copilot read them natively; Codex needs distinct compile target (config.toml agents).
- Capability matrix documented 2026-08-18 with verification legend; Cursor rules must be `.mdc`; Copilot subagent cost ceiling prevents pinning judge stronger than session—frontier session + light workers.
- Model tiering: frontier orchestrator/judge economics (~96% BrowseComp at ~46% cost cited secondary); Copilot silent fallback requires self-report sanity checks.
- Ralph-style loop: fresh context per iteration, file+git state, circuit breaker, dual-condition exit, judge-gated commits.
- STORY-001 empirical probes (2026-08-18): partial tool/name fidelity results in harness-matrix; Cursor model gating blocked full schema probe.

## Decisions taken

- Canonical format stays Claude Code; bootstrap becomes compiler with four emitters; emitted files committed with generated-by header and VERSION/manifest.
- Model tiers as `{{MODEL_FRONTIER}}` / `{{MODEL_LIGHT}}` configuration; autonomous loop off by default; skills.sh distribution from the kit's GitHub repo.

## Open questions

- Per-field fidelity of Claude frontmatter when loaded by Cursor/Copilot; exact Cursor agents schema; quantitative judge-strength thresholds.

## Where it shipped

Phases A–C implemented kit v0.2.0 era per doc Part 2; subsequent stories through v0.29.0/v0.30.0 extended emitters, loop, forge, memory per cross-linked research docs.
