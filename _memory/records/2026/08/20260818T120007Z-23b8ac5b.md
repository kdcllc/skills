## Problem

The autonomous loop ran one story per iteration. Bounded concurrency needed a judged design before touching loop drivers, because failure modes span write conflicts, breaker state races, memory compaction, and exit semantics under multiple slots.

## Outcome

Shipped design-only STORY-004. Added `docs/design-parallel-dispatch.md` (commit 65b7dbe) with ten required sections, token-safe citations, and mandatory engagement with the conflict-free multi-agent research counter-position. Root README and ORCHESTRATION indexed the doc in commit d42a782. No changes to `skills/setup/templates/loop/` or `_loop/` in this story. Backlog passes: true.

## Key decisions

- Mechanism-neutral section headings so write-set admission, worktrees, and locks remain candidates—not presuppositions.
- Chosen direction documented as a three-layer hybrid (planning-layer admission, driver dispatch, integration/fold-back), argued against locks-only and branch-and-merge isolation.
- Slot refill adapted: refill on slot exit, not on merge events, because the loop never pushes branches by itself.
- Breaker section names non-atomic write plus unparseable-read-reseed race; read-side closure deferred to follow-up implementation stories.
- Citation rendering uses spaced placeholders (`{{ IDE_DIR }}`) so design quotes do not trip template token scans.

## Pitfalls / lessons

- Concurrent story-006 commit added root `.gitattributes` while the design doc still claimed none existed; concurrent fact drift required a citation refresh, not a design rewrite.
- Design shipped unindexed until a combined Phase 6 pass with story-006 to avoid README/ORCHESTRATION write collisions.
