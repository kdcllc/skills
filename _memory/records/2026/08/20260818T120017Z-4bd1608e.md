## What happened

STORY-003 could not publish the kit to the intended personal GitHub namespace from the automation session: `gh` was authenticated as a second GitHub user account without access to the target namespace, while git push identity could still target that namespace via SSH. Cross-account repo creation and `gh pr create` then fail even when local commits and README badges already reference the target repo.

## Root cause

Publish automation assumed the GitHub CLI OAuth user matched the namespace owner and matched the SSH key used for git push. Personal-user targets require `gh auth status` to show the owning user before `gh repo create` or PR flows.

## How to avoid

Before `gh repo create` or `gh pr create` for a personal namespace, verify `gh auth status` matches the repo owner. Unblock by logging in as that user (`gh auth login` / account switch), then rerun the gh command; push separately if SSH already succeeded.

User published manually on 2026-08-19.

## Recurrence

The same OAuth-versus-push split blocked PR automation again in developer-guide-docs (`gh pr create` failed), in forge-adapter-delivery at kit v0.22.0 (`gh pr create` failed), and blocked the memory-store v0.30.0 PR on the gh account — each time the PR was handed over manually after local commits were ready.
