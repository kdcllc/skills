## Decision

When Step 2a detects a sparse workspace, `/setup` may print a recommended folder tree but must not create scaffold files until the user explicitly confirms that tree in the same session. On decline, create no scaffold files.

## Why

Empty-directory installs are high-risk for silent overwrites and wrong stack assumptions. Ask-first plus confirm-before-create keeps the agent from inventing project structure the user did not want.

## Rejected alternatives

- Auto-create a default tree without asking (rejected: user alignment required even when sparse).
- Cookiecutter-style full CI/lint/sample modules in v1 (out of scope).

## Consequences

Setup skill prose must retain the exact confirm phrase and once-per-session evaluation. Future greenfield extensions must preserve the no-create-until-confirm invariant. Non-sparse repos never see Step 2a.
