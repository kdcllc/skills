## Problem

The kit still used `judge` / `qa-judge` vocabulary while harness-design research standardized on **evaluator**. Verification prompts lacked calibration exemplars, execute-before-score discipline, and the two-party contract gate before implementation.

## Outcome

Shipped kit **v0.18.0** (release commit `15e7f18`). Clean one-shot rename to `evaluator` / `qa-evaluator` with **no alias stubs**; stale manifest keys pruned on upgrade. Evaluator templates gained calibration mini-verdicts, hard per-criterion thresholds, and execute-before-score; `eval_depth` on tasks; `templates/skills/feature/templates/contract.md` plus Phase 4 contract gate (later removed in v0.23.0). Token `{{JUDGE_AUTO_FAIL_TRIGGERS}}` → `{{EVALUATOR_AUTO_FAIL_TRIGGERS}}`. Verdict spellings (PASS, NEEDS FIXES, etc.) unchanged. Repo re-emitted so instances contain no `*judge*` agent files. Goal closed with Phase 7 commit user-gated; follow-up backlog noted instance frontmatter drift (STORY-014).

## Key decisions

- Keep implementer/test-writer/terminal names; do not rename implementer to generator.
- Historical provenance comments in loop drivers and harness tests stay verbatim; live references only rename.
- Instance + manifest re-emit owned exclusively by task 08 after canonical land.

## Pitfalls / lessons

- Version-pinned assertions in `tests/loop-harness/run.sh` (0.17.0) broke the final audit until bumped to 0.18.0 — version literals in guards need explicit ownership on VERSION bumps.
