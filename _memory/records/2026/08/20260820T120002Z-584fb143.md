## Problem

Loop drivers were strictly serial with global CB0/CB1/CB2 handling. The parallel-dispatch design called for slot supervision, worktree isolation, and per-slot circuit breakers, but concurrent N>1 would duplicate story claims until driver-owned dispatch existed.

## Outcome

Shipped kit **v0.11.0** in commit **25e4f57**: restructured bash and PowerShell loop drivers with slot table, `available_slots` accounting, kill-0 supervision poll, per-slot CB1/CB2, CB0 run-fatal scoped to worktrees when enabled; **double dark launch**—`LOOP_SLOTS` reads design default 2 but clamps to effective 1 until STORY-011; `LOOP_WORKTREE` defaults 0 (main-tree behavior equivalent) with optional worktree path and new **exit 5** for preflight and non-ff integration failures; setup SKILL gitignore append for `.loop-worktrees/` and breaker temp orphans; harness grew to 63 passing assertions.

## Key decisions

- Child subshell runs CLI only; driver owns HEAD capture, sentinel scan, breaker, CB evaluation, integration (data via per-slot mktemp output files).
- Worktree preflight requires tracked `_goals/backlog.md` and instance IDE directory inside the worktree (directory probe, not a single skill file path).
- Identifier preservation: harness-extracted lines (`output`, sentinel grep, prompt read, `detect_rate_limit`) stay byte-identical through restructure.
- checks.sh parity for kill-0 deferred to harness (instance checks.sh untracked).

## Pitfalls / lessons

- Worktrees check out tracked files only; gitignored instance dirs make worktree=1 inoperable in this repo—harness sandboxes prove the path.
- PowerShell must gate `git worktree add` failures; ungated add mislabels failures as exit 5 and can destroy quarantine branches on rerun.
