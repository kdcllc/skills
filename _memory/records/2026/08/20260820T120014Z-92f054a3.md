## Problem

Orchestration skills were auto-discoverable at session start, so agents could invoke phase-gated or driver-owned skills (`align-docs`, `ship-pr`, `auto-loop`, criteria, `test-ladder`) without the orchestrator routing them. Noisy rung-3 commands also flooded the frontier orchestrator context.

## Outcome

Shipped kit **v0.16.0** (release commit `1b87cd4`). Seven P0 templates gained `disable-model-invocation: true` while keeping user `/name` where applicable; `feature`/`research` stay auto-invocable. Phase 6/7 load via path-Read; loop `PROMPT.md` starts with `/auto-loop`. New light-tier **`terminal`** agent (`tools: Bash, Read`, compact return: exit code, ≤30-line excerpt, log path) — orchestrator spawns it for rung 3 / noisy read-only work instead of running `{{FULL_TEST_COMMAND}}` in the frontier session. Emitters preserve flags and register `terminal` on all four harnesses (Copilot nesting default stays off). Structural guard `tests/templates/invocation-flags.sh` locks the surface.

## Key decisions

- Scope A + terminal in one goal; criteria/ladder stay flag-in-place (not demoted to `reference/`).
- Orchestrator retains rung-3 **authority** (after Phase 5 APPROVED); **execution** moves to `terminal`.
- Codex registers `[agents.terminal]` so glob copies are not dangling.

## Pitfalls / lessons

- `/name` inside skill bodies is not a documented bypass of `disable-model-invocation` — path-Read and leading `/auto-loop` are the supported call sites.
- User bumped version mid-goal (0.15.0 → 0.16.0 after terminal purpose correction); instance `terminal.md` still required `/setup` refresh until re-emit.
