Decision (goal release-240-leftovers, agent-kit 2.4.0): the loop driver classifies a backlog `attempts:` value before any bash arithmetic. A value is numeric when it matches `^[-+]?[0-9]+$` and is not an octal-invalid digit string (`^[-+]?0[0-9]*[89]`). Only numeric values reach the unchanged `(( _bl_cur_attempts < 3 ))`, so bash's own octal, sign and overflow rules still decide them. Every other value is warned (`!!! backlog: <id> has an invalid attempts value '<v>' -- INELIGIBLE`, once per id per run) and skipped.

Alternatives considered:
(1) Keep evaluating every value bash accepts, and reject only crashes. That keeps the arithmetic-injection path: `_bl_id[$(cmd)0]` runs cmd because `_bl_id` is a set driver array.
(2) A denylist of `$`, `[` and backticks. Weaker, and still evaluates names and expressions.
(3) Normalize with `10#`. That would turn `08` into 8 (the user asked for warn-and-skip) and change `07`/`010`, which are octal 7/8 today.
(4) A narrow `^(0|1|2)$` guard, tried and reverted in the progress-line goal. It skipped valid `-1` and `00`-`02`.

Rationale: the user's rules were (a) non-numeric values warn and skip, and (b) every value bash evaluates today keeps its result, with only digit-string examples. They overlap on empty, `1+1`, hex and set names. The digit-string reading satisfies (a) and (b)'s examples and closes the injection. The Phase 3 evaluator accepted it; the parent request forbade re-asking, so it was disclosed in the final report and release notes.

Consequences: empty, `1+1`, `0x1`, tab-padded, `-+1`, `--1` and `base#n` values that were selected before are now skipped with a warning. `priority` is still compared raw and should get the same treatment.
