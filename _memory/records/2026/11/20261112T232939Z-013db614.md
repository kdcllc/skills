Goal advisor-audit-mode: outcome shipped to a pull request as orchestration-advisor 0.3.0 (2026-11-12).

What changed. The skill gained an audit mode for projects that already run an orchestration system. After Step 2 the skill asks "Recommend a setup, or audit the existing one?", pre-selecting the answer the signals suggest and showing the values behind it. Audit mode adds Step 4 (Map): each orchestration system is mapped separately with its entry point, phases, gates, agents and their role per flow, shared state, loop control, and the enforcer of every gate (hooks, rubrics, CI, model routing, git hooks, cycle rules, or prompt-only). Higher tiers are found by pattern only (a system that launches entry points running their own gated loop) and are mapped at their boundary, never re-architected without the user's opt-in. Decide applies six rules: Shapes compose, Tier rule, Per-flow overlap, Enforcer rule, Honesty rule ("the current design fits" when nothing material changes), Material change (only visible failures count; "fewer agents" is not one). references/audit.md holds the procedure; references/report-audit.md defines the chat summary, the save offer and an eleven-heading full report with a mermaid map per system. inspect.sh grew from 18 to 25 keys (hook entries, git hooks, rules, rubrics, commands, harness config files, orchestrator skills, with the advisor excluding itself). The guard checks the new files, step order, audit headings and rule names; the suite grew from 86 to 132 cases and ships one generic markdown regression scenario.

Key decisions. The mode is asked, not computed, because a word-match signal would put any project with orchestration skills installed into audit mode. Tasks ran in three parallel waves against a frozen interface in goal.md. Version bump and CHANGELOG heading were moved into one task so validate-skills never sees a mismatch.

Remember next time. Check that the local base branch matches origin before branching; this goal started from a stale master and had to be moved mid-execution. Context-package notes from the plan evaluator can contradict a task requirement; the requirement wins. Regression scenarios taken from a real user's project must be made generic before anything is written to a tracked file.
