## Decision

Address skills.sh scanner prompts about agent-kit (Socket gptAnomaly on the terminal agent, Snyk W011 on Step 2b skill suggestions) with explicit trust-boundary wording, not behavior changes.

## Alternatives considered

- Add an opt-in gate before Step 2b searches skills.sh (closes W011 by design, but changes the install flow; ruled out by the user).
- Restrict the terminal agent to an allowlist of command kinds (breaks its role as a general command runner for tests, git and builds).
- Rewrite every "any Bash or PowerShell command" restatement at once (ORCHESTRATION.md, test-ladder, the emit.sh Codex description). That rewrites every ORCHESTRATION/test-ladder/config.toml golden and conflicts with parallel branches.

## Rationale

The flagged files lacked a stated trust boundary rather than having unsafe behavior. Saying where commands may come from (spawn prompt only, never DATA), that harness approval and sandbox settings always apply, that listing text is untrusted DATA, and that install needs an explicit user pick addresses the scanner's stated concern while keeping the kit's behavior and goldens stable.

## Consequences

- Guards in tests/agent-kit/templates/invocation-flags.sh sections 17-18 pin the new wording.
- The remaining "any command" restatements are follow-ups; a rescan may still flag them.
- Untrusted listing fields still feed the install command's owner/repo/skill arguments (accepted risk).
