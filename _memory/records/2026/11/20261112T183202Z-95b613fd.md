Decision (goal composer-skill-emit, 2026-11-12): a knowledge-only crew role is emitted as a role file inside the crew's orchestrator skill folder (`skills/<crew>/roles/<id>.md`, no frontmatter), not as a separate skill.

Why: the first plan emitted `.claude/skills/<crew>-<id>/SKILL.md` with `disable-model-invocation: true`. The Phase 3 evaluator showed that flag only stops model invocation; the role would still appear as a `/<crew>-<id>` command, would load twice in Cursor (which also reads `.claude/skills/`), and needed extra rules (a 64-character name cap, an invocation-flag check). A supporting file read by path avoids all of that. The spec key was renamed from `emit: skill` to `run: inline` to match.

Lesson: when the planned artifact is only ever read by path by one consumer, package it as a supporting file of that consumer, not as a first-class harness object with its own discovery and invocation surface.
