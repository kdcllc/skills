Goal release-240-priority (agent-kit 2.4.0, pre-PR follow-up). Outcome: shipped as local commits on feat/agent-kit-loop-follow-ups on top of the 2.4.0 release commit f775992, which was not amended: 924acda driver, c52367e tests, plus a docs commit. No push, PR or tag; the version stays 2.4.0.

What shipped:
- The loop driver's backlog `priority:` field went through the same check as attempts. `(( _bl_cur_priority < _bl_priority[j] ))` in `_loop_bl_flush` used to compare raw text. `priority: x` crashed the driver once another eligible story existed, and `_bl_id[$(cmd)0]` ran cmd. A story alone in the backlog was never compared, so it was dispatched whatever its value.
- Two shared helpers now serve both fields. `_loop_bl_int_ok` accepts `^[-+]?[0-9]+$` unless the value matches `^[-+]?0[0-9]*[89]`. `_loop_bl_warn_invalid <field> <id> <value>` prints `!!! backlog: <id> has an invalid <field> value '<v>' -- INELIGIBLE` once per field and story per run, using the `_bl_warned_invalid` string record.
- Only candidate stories (`passes: false`, `blocked: false`) are checked, and both fields are checked. A story is inserted only when attempts is valid and < 3 and priority is valid. Accepted values keep the exact base order, ties included (strict `<` keeps file order).
- Lint is unchanged (it already rejected bad priority and never evaluates it).
- CHANGELOG 2.4.0 gained Fixed and Security bullets, and its upgrade note now covers priority (tab-padded `3<TAB>` was accepted before and is now skipped).
- progress-line.sh gained cases p (parity), q (invalid), r (injection) and an extended m: PASS 45, about 46 s standalone and 33 s inside run-all, against a 59 s cap.

Audit: every arithmetic context in loop.sh was checked. Priority was the last raw backlog field. The operator-supplied MAX_ITER argument, LOOP_SLOTS and LOOP_WORKTREE still reach arithmetic raw (follow-up). CLI token fields are regex-limited to digits and can't inject.

Remember next time: progress-line.sh is near its runtime cap, so budget any new driver cases. Headless test-writer runs that end with a background wait loop return only their last message in `claude -p --output-format json` `.result`; recover the full report from the session transcript, or tell workers to run in the foreground.
