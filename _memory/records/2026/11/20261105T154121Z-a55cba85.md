Decision (agent-composer runtime protocol, after QA): a generated crew's orchestrator writes the user's request into every root input (a file some agent lists in inputs that no agent lists in outputs; tasks.yaml excluded) and always passes it to steps whose needs is empty; on an evaluator FAIL it counts the cycle first and applies on_exhaustion at max_cycles without renaming or re-running, otherwise renames the current reports to <base>.cycle-<n>.report.md and re-runs; it writes the run report to <workdir>/<run-id>/run-report.md (reserved name, prose only).

Alternatives considered: a reserved request.md input with a validator warning for unproduced inputs (evaluator devil's-advocate suggestion); making placeholder model IDs an error in tree mode instead of the S040 spec warning; tree-mode stale-spec detection (left in backlog B88).

Rationale: the bundled content and coding crews would block at their first step without a producer for topic.md/task-brief.md; warnings keep the shipped placeholder examples valid (exit 0); count-before-rename guarantees the evaluator runs at most max_cycles times.

Consequences: every root input receives the full request (B86 for per-task briefs); run-report.md and the gate wording are enforced only by prose (B92, B95); references/patterns.md:215 still states the old order (B96).
