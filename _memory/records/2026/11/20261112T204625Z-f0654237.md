Implementer and test-writer reports in this repo's /feature runs tend to be condensed even when the context package asks for verbatim command output; an acceptance criterion that requires "command and full output in the report" then fails evaluation on evidence form alone (composer-followups task 02: two extra evaluator rounds, no code change).

How to apply: when a criterion needs full scratch-run output, say in the Output section "VERBATIM and complete (not condensed — the evaluator rejects summaries)" and list per-case what to quote; or let the evaluator's own re-run be the evidence and record that ruling in criteria-evidence.md, pointing at a report section that really holds full outputs (check with grep before ruling). Also: when the orchestrator adopts evaluator notes as line patches, amend the task requirement in the same step, or the re-evaluation fails as a criteria-defect.
