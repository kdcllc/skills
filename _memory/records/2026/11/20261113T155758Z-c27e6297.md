Pitfall: a dry-run/price flag in a shell script that wraps paid runs can fall through into the paid path or misprice.

What went wrong: compare.sh --plan --runs 08 hit bash octal parsing in $(( )), the arithmetic failed, and execution continued past the plan branch into real runs. The first fix moved the arithmetic to awk printf "%d", which overflows at 2^31 in busybox awk and mawk and printed a negative run count and cost bound with exit 0.

How it was detected: evaluator probes with a sentinel stub CLI (a fake EVAL_CLI that touches a file) under bash 5 and bash 3.2 with busybox awk.

How to avoid: end a plan branch with an unconditional exit 0 and make every computation in it `|| die`; normalise integers with $((10#$x)) after validating digits and capping length (strip leading zeros first); format large products with awk "%.0f", not "%d"; reject empty option values the same way the wrapped script does; prove "never calls the CLI" with a sentinel stub, under the oldest supported bash and awk.
