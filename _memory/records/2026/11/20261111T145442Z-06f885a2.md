What went wrong. Starting a new /feature goal runs `_kit/memory.sh prune --apply` in Phase 2. That prune deleted the scratch folder of the already-delivered goal (`_memory/work/goals/orchestration-advisor/`), including its `follow-ups.md`. The new goal's scope was defined as row numbers of that file, so the plan evaluator found the scope source missing and could not check any row-to-requirement mapping (blocker at Phase 3 attempt 1).

How it was detected. The Phase 3 evaluator tried to read the file and found only the new goal's folder; the orchestration log showed "Prune: 6 deleted, 2 kept".

How to avoid it. When a new goal is scoped from a delivered goal's follow-ups, copy the row text into the new goal's goal.md (and carry the rows for later goals into the new follow-ups.md) before running the Phase 2 prune, or read the rows from the merged pull request body's "Backlog (not fixed here)" section, which survives. Never reference a pruned goal's scratch path as the scope source.
