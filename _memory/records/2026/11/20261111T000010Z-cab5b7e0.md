Decision: signal counts in the orchestration-advisor inspection contract are per distinct name, and the description-size estimate is Claude Code only.

Alternatives considered. (1) Sum agent files, description characters and skill files across all four harness folders; this was the first draft. (2) Emit separate keys per harness for every count. (3) Count distinct names across harness folders, add one Claude-only agent count, and keep the description keys Claude-only; chosen.

Rationale. A project that mirrors the same agents to Claude Code, Cursor, Copilot and Codex, as an agent-kit install does, would report two to four times its real agent count under option 1, and the summed description size would be compared with a 15,000-token warning that applies only to Claude Code's own custom subagents. Option 2 fixes that but grows the contract with keys nothing reads. Option 3 keeps 18 keys.

Consequences. Agent names strip the longest of .agent.md, .md or .toml, because Copilot agent files end in .agent.md; without that, a Claude plus Copilot mirror still double counts. Walks for agents and skills follow symbolic links so a skill folder linked between roots is found once, and a link cycle must not fail the script. Known undercounts are documented: Codex agents declared only in config.toml, and skill folders named like skipped directories.
