Decision (goal regression-proof-resume, agent-kit 2.3.0): orchestration progress lives in a per-goal `_memory/work/goals/<goal>/progress.md` on every install. Before this change it lived there only when the kit guard was on; otherwise it was kept in ORCHESTRATION.md. The orchestrator writes the file as a whole-file rewrite from the feature skill's `templates/progress.md`. There is no new tool and no log-spawn.sh change. Resume follows `reference/resume.md`: it is offered in Phase 2 or triggered by "resume <goal>", and it is never automatic. It cross-checks the spawn ledger, then verifies the repository: fetch, branch, HEAD at this write, base ancestry, and merged PRs via is-ancestor (exit 128 handled, squash merges detected). Any mismatch stops the resume and asks the user.

Alternatives considered: a progress section in ORCHESTRATION.md for unguarded installs (rejected: two homes, and a kit-owned file gets mutated); a dedicated checkpoint tool or log-spawn.sh subcommand (rejected: more surface, and the template is enough); auto-resume (rejected: stale state could act on a moved repository).

Regression-proof rules have a single home in the test-ladder skill. The agents, task-criteria and the evaluator point to it and do not restate it; a suite case checks that phrases like "equivalent mutation" appear only there. Proofs run on scratch copies (EMIT_KIT for kit suites), never on the real tree or the gitignored instance.

Consequences: guard-on and guard-off installs now emit the same feature-skill progress line, and kit-guard check (n) asserts it for both. The feature SKILL.template.md byte budget (11264) is nearly used up: 11244 bytes after this goal.
