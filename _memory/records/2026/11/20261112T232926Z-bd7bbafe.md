Decision: orchestration-advisor chooses between design and audit mode by asking the user, with a suggested answer computed from the inspection signals, not by a mechanical rule.

Alternatives considered. (1) Mechanical rule: audit whenever agent_files, agent_kit_installed, composer_crews or orchestrator_skills is non-zero. (2) A separate auditor skill sharing inspect.sh. (3) Ask the user at the end of Step 2, pre-selecting the signal-suggested answer and showing the values behind it; chosen by the user at a Phase 3 escalation.

Rationale. orchestrator_skills is a word-match heuristic (subagent, spawn, task tool); any project that installed an orchestration skill would always land in audit mode, including the advisor itself before self-exclusion was added. Plain project subagents with no orchestrator would also be ambiguous. Asking keeps the signals as evidence and removes the false trigger. A separate skill would have duplicated the contract, guard and tests.

Consequences. Step 1 never chooses a mode; Step 2 ends with the question and waits. When the user picks audit with only plain subagents present, the main session that delegates to them is the entry point of one system. The report records the chosen mode and the suggestion values.
