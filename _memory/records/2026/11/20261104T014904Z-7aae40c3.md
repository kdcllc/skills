What went wrong: in a Cursor session with no subagent tool, verdict roles ran as headless `claude -p --agent <role>` processes. Midway through Phase 5 the Claude Code 5-hour usage limit hit; `claude -p` returned exit 1 with "You've hit your 5-hour limit · resets <time>" as the whole result, so the spawn's report file held only that line.

How it was detected: the report file was 65 bytes; the spawn helper printed `claude rc=1`.

Alternatives checked: `cursor-agent -p` failed with "Authentication required" even though `cursor-agent status` said logged in; `copilot -p` rejected every pinned model id and ran only with `--model auto`, which bills AI credits and does not report the model, so it is unfit for a frontier verdict gate.

How to avoid or handle it: check the report size and exit code after every headless spawn; on a usage-limit message, log the failed spawn as `spawn failed: usage limit` with model `not launched`, keep the package, wait for the reset, and re-spawn the same agent type with the same package under the next spawn number. Run long suites while waiting so the rung-3 result is ready. Do not self-evaluate or switch to an unpinned model to save time.
