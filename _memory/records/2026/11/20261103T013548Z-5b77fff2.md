Decision (agent-kit 2.2.1): the bash loop breaker ignores stale probe results by comparing models, and stores the pre-probe model in a 14th state key.

- The filter matches on model equality. `breaker_record` takes an optional 4th argument, the model a slot was dispatched with, and the driver passes `slot_model[s]`. While `probing == 1`, a result from any other model is a no-op with one stderr line.
- The filter covers probes only. The user chose not to extend it to ordinary HALF-OPEN recovery, to CLOSED after a probe closes, or to OPEN after a probe fails. Those are follow-ups B1–B3.
- A new `preProbeModel` key, a string that may be "", is written last. It is optional on read: legacy files derive chain[preProbeIndex] only while probing.

Alternatives considered:
- A probe-generation counter (`probeEpoch` key plus `slot_epoch[s]`). Rejected for now as a larger schema and driver change, but it would cover B1–B3 and chain[0] slots dispatched before the fallback with one rule (follow-up B4).
- A driver gate that starts a probe only when no other slot is running. Rejected: with two or three busy slots the probe could starve.
- A sentinel `preProbeIndex = chain length` meaning "past the end" instead of a new key. Rejected: it overloads an existing key's meaning.

Rationale: model identity is already captured per slot (`slot_model[s]`) and recorded in the ledger. The filter needs no new driver state, and 3-argument callers keep 2.2.0 behavior apart from the corrected restore.

Consequences:
- The breaker state file now has 14 keys, and 2.2.0 reads it safely (downgrade verified).
- A chain-end slot with no model pin is reported as `model ''` (follow-up B15).
- A chain[0] slot dispatched before the original fallback and still running when a probe starts would count as probe evidence. That is rare and accepted.
