Decision: on opt-in agent-kit installs, resuming an unfinished goal goes through the explicit command `/feature resume <goal>`. It does not go through a natural-language request.

Why: with flags.opt_in the feature skill carries disable-model-invocation: true, so the model never loads it on its own. The earlier opt-in description promised that it "runs only when the user types /feature or asks to resume a goal". Nothing could route the second half.

Alternatives considered:
- Keep the phrase and add an always-loaded rule on every harness telling the model to suggest the command. Rejected, because always-loaded text is kept minimal.
- Drop resume from the opt-in sentence entirely.

Consequences:
- The opt-in description names "/feature resume with a goal name". Descriptions stay free of < and > for claude.ai sync.
- Cursor's always-loaded opt-in orchestration.mdc and reference/resume.md name `/feature resume <goal>`. Body text may use angle brackets.
- The opt-out sentence keeps "or when the user asks to resume a goal", since auto-invocation works there.
- Other harnesses' pointers are not opt-in-specific, so they carry no hint.
