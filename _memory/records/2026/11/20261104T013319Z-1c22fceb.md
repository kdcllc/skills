Goal progress-line (agent-kit, for 2.4.0; no version bump). Outcome: committed locally on branch feat/agent-kit-progress-line (base 26ba50f), no push or PR.

What shipped:
- Feature progress line. The feature orchestrator opens its user update at every `progress.md` rewrite with `Progress: <pct>% (<done>/<total> steps, metric v1); <current unit>, <in flight>.` and writes the same line as the `progress:` header (line 5) of `progress.md`. Feature metric v1: steps are the enabled phases (1-5, plus 6/7 per `goal.md` `phases:`) plus the Phase 4 task files; a step is done at its gate (Phase 1 at user confirmation, Phases 2-3 at the goal-evaluator PASS, tasks at PASS / PASS (with notes), Phase 4 when all tasks are done, Phase 5 at exit, Phase 6 at the doc audit, Phase 7 at PR / hand-over / logged skip); floor percentage. The single definition is the new `templates/skills/feature/reference/progress-line.md`; the feature SKILL.template.md points to it from Goal checkpoint and resume (two trims kept it at 11233 bytes, budget 11264), `reference/resume.md` and the four ORCHESTRATION File Locations trees mention it.
- Loop progress line. `loop.sh` prints one stderr line after every reap: `Progress: <pct>% (<done>/<total> steps[, <B> blocked], metric v1); <story> attempt <n> <outcome>, <in flight>.` Loop metric v1: steps are the backlog stories, done is `passes: true`, blocked is not done and `blocked: true` or attempts >= 3 (counted in the total, shown only when > 0). Defined in the `# PROGRESS:` header; one sentence in the loop SKILL template.
- New suite tests/agent-kit/templates/progress-line.sh (11 cases, regression-proven); goldens regenerated; docs in feature-workflow.md, autonomous-loop.md, contributing.md, architecture.md.
