Goal composer-unhashable-id (2026-11-13) fixed GitHub issue kdcllc/skills#20 in agent-composer, released as 0.3.2 (PATCH) on branch fix/composer-unhashable-id. 0.3.1 was taken upstream mid-goal (PR #21, per-skill README), so the branch was fast-forwarded to origin/master and re-bumped per AGENTS.md. Outcome: shipped (PR pending).

- Bug: `composer.py validate spec` raised `TypeError: unhashable type` when a step `id` was a YAML list or mapping in any spec with more than one agent (no gate needed). The second loop of the S044 block tested `st.get("id") in on_fail_steps` (a set) without a str check; the earlier S006 "must be a string" finding was lost behind `error: internal`.
- Fix: the issue's shape — skip non-dict steps, `sid = st.get("id")`, `isinstance(sid, str)` before the set membership tests. No finding code/message changed; validate output on all 72 existing specs is byte-identical.
- Audit: a leaf fuzz (replace every scalar in every fixture/example spec with `[]` then `{}`, flag `internal`/`Traceback`) found 148 crashes in 2524 runs before the fix, all at `steps[N].id`, and 0 after. Helpers step_ids/agent_ids/needs_graph_has_cycle/transitive_needs and validate_pattern already guard with isinstance.
- Tests: fixtures s006-step-id-list / s006-step-id-mapping and cases spec/S006-step-id-{list,mapping} in tests/agent-composer/run.sh (130 cases). They fail on the 0.3.0 composer.py via AGENT_COMPOSER_SKILL_DIR.
- Lesson: check `git ls-remote --tags origin '<skill>/*'` and origin/master before fixing the bump number; another PR can release the same skill while a goal runs.
- Backlog: container-level fuzz (whole step or gate replaced by []/{}) never ran.
