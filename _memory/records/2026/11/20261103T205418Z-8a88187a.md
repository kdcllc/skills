Pitfall: a fast-tier `terminal` subagent asked to "return search output verbatim" can paraphrase hit text, and a consumer trace built from its reply then quotes text the repo does not contain.

What happened (goal memory-prune-followups, 2026-11-03): the Haiku `terminal` returned S2's hit for `docs/agent-kit/guide/feature-workflow.md:160` ending "never block Phase 2." — the file says "never block." It also printed `hits=2` above a three-line block. The Phase 3 evaluator caught both by re-running the searches.

How to avoid:
- Have `terminal` redirect each search to a file under the goal folder (`rg … > _memory/work/goals/<g>/searches/S<n>.txt; echo rc=$?`) and return only exit codes and `wc -l`; paste `## Searches` blocks from those files.
- Count hits from the file, not from the agent's summary line.

Related: when the Cursor session has no subagent tool and headless `cursor-agent` is unauthenticated, `claude -p --agent <role> --model <id> --output-format json` in the worktree is a working fresh-context spawn path; keep the `session_id` from the JSON to resume an evaluator for Phase 3 deltas and searches round trips.
