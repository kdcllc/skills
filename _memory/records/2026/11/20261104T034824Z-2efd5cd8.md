Pitfall: bash arithmetic on text from a file runs commands embedded in it.

What happened (goal release-240-leftovers): the loop driver evaluated the backlog `attempts:` field with `(( _bl_cur_attempts < 3 ))`. Inside `(( ))` a variable's value is evaluated recursively as an expression. A value naming a set array with a command substitution in the subscript, for example `_bl_id[$(touch${IFS}/tmp/m)0]` (no spaces; the parser strips spaces), ran the command. An unset name such as `x` aborted the driver under `set -u` (unbound variable), and `08`/`09` printed raw `value too great for base` errors.

How detected: an empirical probe on the base driver while planning. It ran the real driver in throwaway repos with one value per run, and a marker file proved the command ran.

How to avoid: never put raw file or user text inside `(( ))`, `$(( ))`, `[[ -lt ]]` or array subscripts. Validate first with `[[ $v =~ ^[-+]?[0-9]+$ ]]` and reject octal-invalid digit strings (`^[-+]?0[0-9]*[89]`), or force base 10 with `10#` when octal semantics don't matter. The loop driver's `priority` field still has this problem (follow-up B1 of the goal). Pin the fix with a test that uses an injection payload and asserts the marker file is never created.
