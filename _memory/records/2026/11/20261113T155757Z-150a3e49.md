Decision: agent-kit candidate changes are stored as unified-diff patches (tests/agent-kit/evals/candidates/<name>/patch.diff, applied with git apply -p1 to a scratch copy of skills/agent-kit, templates/ only), not as branches or kit copies.

Alternatives: a git branch per candidate (hard to compare side by side, rots against master); full kit copies (large, drift silently).

Rationale: a patch is small, reviewable, applies to the current kit or fails loudly (compare.sh exits 3), and lets compare.sh build every arm from one checkout. A one-line backticked marker per candidate proves the patch reached the emitted .claude/ tree and is absent from the stock emit.

Consequences: candidates are temporary — a later goal adopts one (with a version bump) or deletes it. Because the contract limits patches to templates/, a candidate cannot fix guards or pins outside templates/; adoption must update those (see the k1-spec/k2-rightsize regression-proof-resume.sh failures). The self-test SKIPs (not FAILs) the cases that need a real candidate when none exists.
