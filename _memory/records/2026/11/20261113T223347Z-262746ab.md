Pitfall: evidence summarised from a deduplicated or truncated run is not evidence.

What went wrong: during pre-flight for goal composer-unhashable-id, the orchestrator ran the agent-composer fuzz piped through `sort -k2 -u | head -40` and recorded "exactly two crash rows" in criteria-evidence.md. The Phase 3 evaluator re-ran the fuzz as specified and saw at least 148 rows across 33 specs, so it returned NEEDS REVISION. The conclusion (only steps[].id crashes) was right, but the recorded claim was not, and no command was written down.

How to avoid: record the exact command that produced the evidence, and summarise its full output (counts, distinct paths) rather than a filtered view. For content-inspecting checks record a true negative and true positive at the same time.

Related: subagents whose long commands the harness auto-backgrounds (over ~120–180 s) can stop and report "waiting on background work" with nothing actually running. Tell them in the brief to wait for every command to finish before returning; if one stalls, resume it with a message asking for the verdict.
