Decision (agent-kit, after 2.3.0): the loop breaker ignores stale slot results by a probe epoch, not by model equality.

- State key `probeEpoch` (non-negative integer, written last) increments on every change of the model slots dispatch on: a chain advance (CLOSED/HALF-OPEN/OPEN-defensive to OPEN), a probe start, and a failed-probe restore. It does not change on OPEN to HALF-OPEN, HALF-OPEN to CLOSED, a successful probe, probe scheduling, or the fail-safe (which carries a parsing epoch, else 0).
- The driver captures the epoch per slot at dispatch (`breaker_current_epoch`) and passes it as `breaker_record`'s 5th argument. A mismatching epoch means no state change plus one stderr line: `breaker: ignoring stale result from model 'X' at epoch N (current epoch M)`, or `from (no model pin)` for an empty model.
- Compatibility: absent key = epoch 0 (2.2.x files load silently). An omitted or non-integer 5th argument falls back to the 2.2.1 rule (4th-argument model filter while probing).

Alternatives considered: extending the model-equality filter (decision 20261103T013548Z-5b77fff2) to every state. Rejected because chain[0] slots dispatched before a fallback share the probe's model, so only a generation counter separates them, and three separate filters would be needed for B1-B3.

Consequences: every advance bumps the epoch even at chain end, where the model stays empty; a second slot rate-limited on the same model is ignored, so the chain advances once per burst. Tests and docs: loop-retry-breaker.sh cases 22-28 and 30; ORCHESTRATION.md and docs/agent-kit/guide/autonomous-loop.md Model breaker rows.
