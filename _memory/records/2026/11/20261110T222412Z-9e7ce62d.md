Two-pass study on 2026-11-10 of how to choose a multi-agent orchestration pattern, compared with agent-kit 2.4.0 and agent-composer 0.1.0. Pass 1 was four Anthropic articles; pass 2 was an external deep-research report, with seven of its claims re-checked against live pages.

Findings. A single agent plus skills is the default across Anthropic, OpenAI and Cognition. More agents are justified by context pollution, independent parallel units, tool or prompt conflict, or black-box verification. Splitting by type of work (plan, build, test, review) is the documented anti-pattern. Anthropic puts multi-agent token cost at 3-10x a single agent, a separate figure from its 15x-versus-chat number.

Test authorship. arXiv 2607.05139 (checked) found tests written after seeing faulty code detected 14% of faults against 25% for independently written tests. A separate test author therefore helps only when it works from the spec. agent-kit's test-writer is given the implemented modules and reads them, and agent-composer's coding-crew test-writer reads the implementation summary, so both carry the handoff cost without the independence.

agent-kit's black-box evaluator, fix-cycle caps and cross-family rotation match the best-supported pattern. Candidate gaps: the test-writer arrangement, no right-sizing gate before the seven phases, and no outcome eval set. agent-composer candidates: a role-first interview, a qualitative crew-or-not test, no skill-in-place-of-agent output, and no best-attempt-with-caveats exhaustion behavior.

No tool with published results infers a topology from a repository. Closest prior art: Anthropic's unmaintained single-agent-loop-kit (checked) and the community skill multi-agent-system-architect-v2 (not inspected). The only documented decision method is eval-first with about 10 golden tasks.

Harness facts checked on 2026-11-10: Cursor subagents can run in isolated worktrees or cloud environments; Claude Code defaults to 20 concurrent subagents and three nesting layers; Claude Code worktree isolation branches from the default branch and not the parent HEAD, which means ready-group tasks in worktrees would not see uncommitted feature-branch work.

Caveats. Most of the external report came from search excerpts. Copilot parallelism, Codex concurrency keys, and the Kim et al. and MAST figures were not re-checked. No change was adopted at ingest time.
