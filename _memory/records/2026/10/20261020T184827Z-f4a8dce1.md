Decision (goal rule-file-feedback, 2026-10-20, user-confirmed): path-scoped rule delivery to subagents stays a routing policy, not a harness guarantee.

- Kit policy: every rule file whose globs match a task's writes is listed in that task's implementer/test-writer AND evaluator context packages (## Files to Read), final audit included. Rules are cited by path, not inlined.
- The only evidence about on-demand delivery is one Claude Code VS Code extension 2.1.241 field observation (2026-08-25): scoped rules injected only after a Read-tool read; shell reads and editor opens did not trigger them. Templates state it as an attributed past-tense observation ("varies by harness"); the harness matrix records it as IDE-extension-scoped, not CLI-probed, with a re-probe-after-upgrade note. Cursor/Copilot delivery is unknown; Codex has no file-read tool.
- Agent guidance is conditional ("Where your harness has a file-read tool…") so no harness is told to avoid its only way to read files.
- Rejected: preloading rules via skills: frontmatter, unscoping all rules, moving conventions into root CLAUDE.md, a placement-enforcing PreToolUse hook (project-specific, harness-specific), and per-agent project Conventions tables.
