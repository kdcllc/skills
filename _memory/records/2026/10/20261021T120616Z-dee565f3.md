## What went wrong

During Phase 4 of loop-cli-recipes, the orchestrator relayed an optional arbiter suggestion in the implementer's context package ("the external sandbox must be a container/VM; a worktree does not isolate it"). That wording contradicted the user's recorded Phase 3 decision ("external container or worktree sandbox") and the guide's SAFETY note. The task evaluator returned NEEDS FIXES and blamed the implementer for an unreported deviation.

## How it was detected

The task evaluator compared the paragraph against the task requirement and goal.md's decision row, and found the conflict with the guide's SAFETY line and the driver headers.

## How to avoid it

- Never pass an optional evaluator or arbiter suggestion that changes recorded user-decision wording into a worker context package. Raise it with the user first, or record it as a plan amendment.
- When a fix cycle traces back to the context package, log the provenance in the orchestration log and tell the re-evaluation. The evaluator then withdraws the deviation finding instead of penalising the worker.
