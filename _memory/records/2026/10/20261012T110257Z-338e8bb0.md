Open follow-ups after goal memory-followups (agent-kit 1.0.0). None blocks 1.0.0.

Product behavior:
1. pwsh --root containing a literal backslash (Linux/macOS) indexes 0 records: its relpath
   rule replaces every backslash with / (memory.ps1 ~196-197). Pre-existing since v0.30.0;
   the harness SKIPs that parity half.
2. Windows case-insensitive aliases: pwsh loop detection compares canonical paths
   ordinally; an NTFS alias differing only by case could escape it. Check in the Windows
   smoke run.
3. Possible unbalanced-bracket tags divergence: pwsh Parse-Brackets strips brackets only
   when both are present, bash strips each side. Test "tags: [a, b" and "tags: a, b]".
4. getline on a directory path in two hand-edited-manifest cases (empty manifest line;
   TAB-shifted row with --include-superseded) in memory.sh search awk ~1106-1107; not
   reachable through the CLI.
5. Stale-index search is closest to the 1 s budget (0.53-0.85 s at 200 records); watch it
   as the store grows.

Tests and tooling:
6. Harness cases [bash] (i) and (n) x2 fail when sqlite3 exists but its FTS5 probe fails
   (they assume fts: yes whenever sqlite3 is present).
7. search-fm-tab-title: the no-pwsh check should require empty stdout and exactly
   "memory: 0 results".
8. tests/agent-kit/templates/memory.sh ~411 uses GNU sed alternation; switch to sed -E.
9. score_file in memory.sh declares an unused local (cosmetic).

Docs:
10. CHANGELOG [1.0.0] "Unreadable record files" wording: on a fresh index both twins skip
    the row with no line at all.

Process lessons:
11. Implementer evidence scripts must write scratch only under $TMPDIR; save every evidence
    script next to its output.

    packages.
