Decision: secrets are stopped at the single writer and at commit time, not by a hook the kit installs.

`memory add` (both twins) redacts the title and the normalized body before the size check, hashing, dedupe and the admission screen, so ids and dedupe work on redacted content and loop proposals are redacted on the loop.ps1 path too. `memory.sh check` is the commit gate: exit 3 for malformed frontmatter, id/filename mismatch, sha256 mismatch, a secret that redaction would change, an admission phrase under records/, or (with --staged) any staged change to an existing record other than deleting a quarantined file. It reads staged blobs with rename detection off and fails closed on unknown statuses and git errors.

Alternatives rejected: installing a pre-commit hook from /agent-kit (the kit never writes local or user settings; the README gives a one-line opt-in instead); running check inside loop step 3b (redundant with add-time redaction and would need a PowerShell check); a separate redaction tool (duplicated rules drift).

Consequences: a new literal exit code 3; jq stays optional and only `capture` needs it; the false-positive baseline over the existing store was zero before the patterns were frozen, and `check` passes on this repository's own store.
