Goal memory-store-followups (agent-kit memory store follow-ups after Releases C and D), shipped on branch feature/memory-store-followups (based on 8e2cdd3), unreleased.

Outcome:
- **memory.sh capture:** `--idle-hours` accepts 1–6 ASCII digits; 7 or more exit 2 `memory: invalid --idle-hours`.
- **memory.sh backfill, escalations:** checks run in the order open → bad-date → archived → would-add.
  - An entry whose last `- resolved:` line carries an impossible calendar date prints `skip:bad-date`. The Gregorian check (`gregorian_date_valid_p`) was factored out of the `--since` validation.
  - An escalation whose body hash already exists under `records/` or `quarantine/` prints `skip:archived` in both `--plan` and `--apply`. The hash uses the same prepare, normalize and redact steps as `add`, on the same bytes apply writes.
- **memory.sh backfill, research:** the `**Date**:` value has a trailing CR stripped, and the date regex has no awk intervals.
- **Memory README:** documents all of the above, plus:
  - `rm` delete case `exit 1 (untracked)`;
  - `--only` leaves unnamed goals and topics out of the output;
  - the (3c) `19700101T000000Z` fallback;
  - the real `memory.ps1` subcommand list;
  - the 5-column `.distilled` ledger.
- **memory-capture skill and reference:** a session whose current raw `sha256` differs from its latest non-empty 5th column is offered again, and the new record passes `--supersedes` with the previous record id.
- **Evaluators:** the evaluator agent has a read-only-harness rule, and feature Phases 4 and 5 always launch the evaluator. When it runs read-only, the orchestrator first spawns `terminal` for each acceptance-criterion command.
- **goal-criteria:** has a generic leak check against copying the project's own goal slugs, record ids or titles into templates it distributes.
- **ORCHESTRATION wording** is fixed.
- **Tests:**
  - Twin-parity and release-c proofs use shared predicates with built-in negative controls.
  - No GNU `sed -i`.
  - Every backfill mutation states its changed-line count.

User decision mid-goal: commit 8e2cdd3 had converted `templates/tools/bash-launcher.cmd` to LF, which broke `windows-launcher.sh`. The kit needs that file in CRLF, byte-identical to `bin/emit.cmd`, so it was restored from 8e2cdd3^ and the `.cmd` goldens went back to CRLF.

Out of scope (user): backfill performance, capture hooks.

Remember next time: write evidence files completely before spawning a read-only evaluator, never in the same parallel batch. Also run long suites behind a lock with a private TMPDIR, because the shell tool can launch a command twice.
