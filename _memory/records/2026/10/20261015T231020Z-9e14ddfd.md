Pitfall: trimming the agent-kit feature skill to fit its byte guard silently dropped rules, and every guard still passed.

What happened: to add two pointer lines, an implementer trimmed `templates/skills/feature/SKILL.template.md` from 11260 to 10557 bytes — about 700 bytes more than needed. The trim removed the "yes when user-facing docs change" Phase 6 default (then present in no template), inverted the `eval_depth: full` rule ("tasks with interface consumers" became "interface consumers"), replaced the full `_kit/log-spawn.sh spawn/outcome/note` command shapes with `spawn …`, and dropped "at comparable tier", "guard trips", "No placeholder lines", and the post-spawn repository-safety cue. All nine structural guards (skill-slimming, template-currency, memory-wiring, invocation-flags, ...) passed because they grep only specific phrases.

How detected: the task evaluator compared the full `git diff` of the skill against the "drop no rule" requirement and listed 11 exact line patches restoring the original wording (net +453 bytes; still under the limit).

Avoid it: when a task must trim to fit a byte budget, require a before → after list of every trimmed sentence in the report, cap the trim to the bytes actually needed, and have the evaluator diff the file rather than trusting the phrase guards.
