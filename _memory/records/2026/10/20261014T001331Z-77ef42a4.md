Goal memory-store-d-backfill (agent-kit memory store Release D), shipped on branch feature/memory-store-d-backfill (worktree, based on the Release C commit 0bb6b77), unreleased.

Outcome: a new bash-only subcommand `memory.sh backfill [--plan|--apply] [--goals] [--research] [--escalations] [--only <name>] [--root <dir>]` turns closed legacy work into records with no LLM step. `--plan` (the default) writes nothing; `--apply` calls `add` once per source as a subprocess with `MEMORY_NOW` set from the source timestamp (converted to UTC in awk), so identical inputs give identical record files. Exit codes: 0, 2 (usage), 4 (an add failed), 5 (something was quarantined). The PowerShell twin prints a bash-only stub and exits 2, like check, rm and capture.

Sources and closed signals: goals get one `goal-summary` each. A goal is skipped as archived when its log has an `ARCHIVED: <id>…` note naming an existing record, or a record already uses the source label `goal <g> (goal.md)` or `_goals/<g>/goal.md`. It is closed when the last Phase 5 evaluator SPAWN has an OUTCOME starting with APPROVED, when a `### <ts> — Phase 5 APPROVED` note exists, or when it is named with `--only`. Research topics with `report.md` become `research-ingest` records, but only when named with `--only`. Topics with an `ingested` marker are already archived. Escalation entries (`## <story-id>: <title>`) with a `- resolved: YYYY-MM-DD <decision>` line become `decision` records. That covers `_goals/ESCALATIONS.md` and `_goals/archive/ESCALATIONS-<YYYY-MM>.md`, ordered by file name, then by entry. From now on the feature archive step logs the ARCHIVED note, and the research archive step writes `_research/<topic>/ingested` (line 1 a UTC timestamp, line 2 the ids). The memory-capture reference documents a one-time transcript back-fill runbook.

Final audit: one major fix. An `--only` goal whose log contained only Phase 5 SPAWN headings got the 1970 epoch id, because the last-heading timestamp skipped those headings. Three minors were fixed too: the memory.ps1 header, a CR strip in the archived check, and the Codex wording in ORCHESTRATION. Each fix has a one-line mutation test.

Remember next time: helpers that track "the last X seen" must update on every matching line, not only on lines a later branch also classifies. Write evidence files completely before spawning a read-only evaluator, or put the evidence inline in the prompt.
