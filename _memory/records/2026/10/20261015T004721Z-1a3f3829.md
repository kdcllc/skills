Goal memory-work-layout (agent-kit: retire `_goals/` and `_research/`; everything under `_memory/`). Shipped on branch feature/memory-work-layout from 9ba4a4e, unreleased. Breaking layout change; no version bump.

## Outcome

**New layout:**
- In-flight goal and research work lives in gitignored `_memory/work/goals/<goal>/` and `_memory/work/research/`.
- Loop state lives in tracked `_memory/loop/` (backlog seed, LEARNINGS, ESCALATIONS, archive/). `breaker-state.json` is ignored.
- Records stay in `_memory/records/` and `_memory/quarantine/`. Only those two are scanned by check, index and search.

**Kit changes:**
- **Contract and wiring:** the memory README and ORCHESTRATION define the layout and the upgrade contract.
- **Tools and loop:**
  - `log-spawn.sh` writes `_memory/work/goals/<goal>/orchestration-log.md`.
  - `memory.sh backfill` reads the new layout. The legacy `_goals/<g>/goal.md` label still counts as archived.
  - The loop drivers (bash and PowerShell) use `_memory/loop/`. The worktree preflight needs a tracked `_memory/loop/backlog.md`.
- **Rules:**
  - The story `writes:` rule forbids only `_memory/records/` and `_memory/quarantine/`.
  - Phase 6 / align-docs treats the whole `_memory/` tree as read-only.
- **emit.sh:**
  - The backlog seed moves to `_memory/loop/backlog.md`.
  - New git lines are added, and retired `_goals/...` lines are removed by exact match. User lines, blank lines, each line's own ending and the final newline are preserved.
  - A two-phase migration runs whenever `_goals/` or `_research/` exist:
    - it plans after `--check-answers`, and conflicts exit 4 before anything moves;
    - it applies after the dry-run exit;
    - tracked files move with `git mv`, then goal and research folders are untracked;
    - `--force` leaves conflicts in place with a warning;
    - the summary reports `migrated N`, and hint lines are printed.
  - An empty `--root` now exits 2.
- **Tests:**
  - `emit-migrate.sh`: 39 checks, including 13 single-line mutations with strict return codes.
  - `legacy-paths.sh`: an explicit allow-list plus two negative controls.
  - A fail-closed `tests/agent-kit/lib/fixture-root.sh` is now used by the touched suites.
  - All suites were moved to the new layout, the goldens were regenerated, and run-all passes 25/25.

**Dogfood:** this repo has no `_goals/` or `_research/`, and 524 of 524 files were verified at their new paths. The `runtime-language` research got an `ingested` marker naming `81273d7a`. Decision records `c630a799` and `b286c9ac` supersede `12faaca4` and `07601b86`.

## Incident

During the Task 07 test-writer run, an empty root variable made `emit --root ""` and `git -C ""` act on the current directory, which was this repo. The repo was migrated early, a stray commit was made as `t@t`, and the local git identity was overwritten. The orchestrator restored everything with nothing lost. Emit now rejects an empty `--root`, and the tests guard their fixture roots.

## Remember next time

- Back up before any task that could touch real user trees.
- Assert fixture roots in every test.
- Write evidence and context files before spawning, never in the same batch.
- Mkdir-lock long commands, because the shell tool can launch a command twice.
