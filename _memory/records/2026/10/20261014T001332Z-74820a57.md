Pitfall: text-processing shortcuts in memory.sh that pass on the host but break on real inputs.

Seen in Release D:
1. `memory.sh` runs with `set -f`, so a glob like `"$dir"/ESCALATIONS-*.md` never expands. Archived escalation files were silently ignored until the scan used `find -maxdepth 1 -type f -name` and sorted by basename.
2. Cutting a body to a byte limit with `head -c` can split a UTF-8 character. `iconv` is not available everywhere, so the cut now inspects the last 4 bytes with `tail -c 4 | od -An -v -tu1` and awk, then drops any partial sequence.
3. Heading patterns need anchoring: `SPAWN evaluator (Phase 5` must be matched after the ` — ` separator with a full timestamp regex, or a title that quotes it would match too.
4. A "last timestamp seen" variable was updated only in the else-branch of a heading classifier. Goals whose only headings were Phase 5 SPAWNs fell back to the epoch id.
5. CRLF logs: every read loop needs `line="${line%$'\r'}"`, including helper loops added later.

How detected: an adversarial fixture tree (CRLF, multibyte at the cut boundary, archived escalation files, logs with only SPAWN headings) run on the host and in `docker run bash:3.2` as root. Each fix is pinned by a mutation test that must change exactly one line.

Avoid it: in memory.sh, never use globs; use find. Never assume iconv. Anchor every log-heading regex on the full `### <ts> — ` prefix. Strip CR in every read loop. For each fix, add a mutation with `expect_changed_lines` so that the mutation edit stays a single line.
