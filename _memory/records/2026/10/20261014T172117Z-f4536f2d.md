Pitfall: mutation proofs and evidence that pass for the wrong reason.

Seen in goal memory-store-followups:
1. **Mutation that rejects everything.** A mutation meant to disable the calendar check replaced it with `&& false`, which rejects every date. It was "caught" only because a valid leap day stopped importing, so the bad-date acceptance it was named after was never exercised. The fix was to remove the check (`s/ && gregorian_date_valid_p "\$resd"//`) and assert the bad date's `skip:bad-date` line.
2. **Mutation by line number.** A mutation addressed a line number (`2736s/.*/…/`) and injected `:` into a single-quoted awk program. awk crashed, the id changed, and the proof passed. `bash -n` cannot see awk syntax errors. The fix was to anchor on content inside the function's address range (`/^fn() {/,/^}/ s/…/…/`) and use a valid awk no-op.
3. **Refactor that silently removes a mutation target.** A refactor deleted the exact line an existing mutation's sed patched. The mutant became identical to the canonical code and the proof stopped testing anything. Keep the patched shape or update the mutation in the same change.
4. **Evidence read too early.** An evaluator was spawned in the same parallel batch as the command writing its evidence file, so it read a partial file.
5. **Double-launched suite.** The shell tool launched a suite twice. Two copies of `memory-wiring.sh` counted each other's `memory-wiring.*` temp roots, and its leak check failed.

How detected: evaluator code reading of each mutation, plus a refused-shell evaluator flagging missing lines in the evidence.

Avoid it:
- Every mutation must break exactly the named behavior, with an assertion on that behavior's output line.
- Anchor seds on content and pass the expected changed-line count.
- Write evidence fully, then spawn.
- Run long suites behind `mkdir` locks with a private TMPDIR.
