## Decision

The kit store is a **git-tracked `_memory/`** tree of immutable markdown records with a local derived index. It **augments** `_goals/` and `_research/`; it does not replace them. In-flight orchestration stays in goal folders; finished knowledge is distilled into records. Native harness “memory” features are never authoritative for kit knowledge.

## Why

Research ingest (2026-10-08) prioritized cross-machine durability, team sharing, offline search, and cross-harness recall without migrating live workflow files into git on every spawn.

## Rejected alternatives

- Harness-native memory as the sole store (rejected—non-portable, harness-specific).
- Replacing `_goals/` with memory records for active work (rejected—loses spawn artifacts and write-set fences).

## Consequences

Record bodies must be self-sufficient because `source` may point at gitignored paths. Releases B–D wire read protocol, transcripts, and back-fill separately. Record `harness` uses `claude`, not `claude-code`, to avoid model-ID tripwires in templates.
