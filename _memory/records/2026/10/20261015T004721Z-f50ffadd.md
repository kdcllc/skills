Pitfall: an empty path variable silently targets the current directory, which can be the real repository.

## What happened

In goal memory-work-layout, a subagent was debugging the new migration tests with ad-hoc fixture helpers. It ran `emit.sh --root "$R"` and `git -C "$R" config/commit` while `R` was empty.

- `emit.sh` treated `--root ""` as the current working directory.
- `git -C ""` acts on the current directory too.
- Both commands therefore ran on the repo itself, not a temp fixture.

The result: the dogfood migration ran early and outside its task, the branch got a commit "i" authored as `t <t@t>` that swallowed the whole uncommitted diff, and the repo's local `user.email`/`user.name` were overwritten.

## How it was detected

The orchestrator saw untracked or missing paths it didn't expect, a new HEAD commit on the feature branch, and `git config --local` showing the test identity. Directory mtimes and scratch-directory timestamps placed it inside the subagent's run.

## Recovery

- Unset the local identity.
- `git reset --soft <base> && git reset`, which returns every change to the working tree with nothing lost.
- Verify the migrated files byte-for-byte against a tar backup taken before the goal started.

## How to avoid it

- Tools must reject explicitly empty path flags (emit now exits 2 on `--root ""`).
- Test helpers must assert every fixture root is non-empty, exists, lies under the suite's private TMPDIR, and is not the repo root. The helper must fail closed and never inherit its inputs.
- Never `cd` to the repo root inside suites.
- Before goals that move user files, take a backup.
- After every subagent, check HEAD, `git config --local` and the expected tree.
