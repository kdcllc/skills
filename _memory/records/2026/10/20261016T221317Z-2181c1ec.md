Pitfall: evaluator-supplied [line-patch] text and implementer self-checks can each be wrong about the very acceptance criteria they cite.

What happened (goal agent-kit-align-docs-working-tree): (1) a task evaluator's required line-patch for the research template wrapped "continue from its Phase 3 / (goal evaluation)" across two lines while claiming every AC literal stayed on one line — applied verbatim it would have broken AC1's `grep -F 'Phase 3 (goal evaluation)'` and the new phase-handoffs guard. (2) In a later task that regenerated emit goldens, the implementer marked the "golden delta limited to research files" requirement NOT DONE because it read `git diff` against HEAD, which also contained an earlier task's align-docs golden changes on the same branch.

How detected: the orchestrator re-checked the evaluator's patch against the task's AC greps before dispatching apply-verbatim mode, moved the line break one word earlier, logged the correction, and told the evaluator in the re-check package (the evaluator agreed). For goldens, the orchestrator had tarred tests/agent-kit/fixtures/emit-golden before the task and diffed against that snapshot: 21 files, research only.

Avoid it: before dispatching any line-patch-only cycle, grep the patched text against the task's AC literals (especially multi-word literals near line breaks). When more than one task in a goal runs `emit-golden.sh --update`, snapshot the golden tree before each later task and judge its scope against that snapshot, not against HEAD.
