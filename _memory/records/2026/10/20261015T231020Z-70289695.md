Decision: agent-kit line-patch fixes are applied by the resumed task executor (implementer or test-writer) in apply-verbatim mode, not by the orchestrator.

Alternatives considered: (a) the orchestrator applies `[line-patch]` fixes itself, which is cheapest but breaks the iron rule "You never write or edit product code yourself"; (b) no tags — the orchestrator detects an old/new-text shape in the evaluator's fix text; (c) the chosen design: the evaluator tags each required fix `[line-patch]` or `[structural]`, and a line-patch-only verdict resumes the same executor on any cycle without model rotation.

Rationale: keeps the coordinator/worker split and the rule that every fix is re-evaluated, while removing design work and model rotation from trivial cycles. Line numbers refer to the file as the evaluator read it and old text is authoritative, so the executor applies same-file patches bottom-up and searches ±10 lines; a missing patch is reported as `NOT APPLIED` and the next cycle takes the normal path.

Consequences: the cycle still counts toward the 3-cycle limit; a mislabeled patch is a `major` issue; continuation-ladder signature and rung-5 comparisons strip the tags. Both `implementer.md` and `test-writer.md` must carry the mode — the first final audit caught that only the implementer had it, after a test task's line-patch cycle had to improvise.
