Pitfall: portable-looking shell and regex constructs that diverge between GNU, BusyBox and .NET.

Seen in Release C: (1) BusyBox `tr` does not support the `[c*]` repetition in string2, so `tr ',[:space:]' '[\n*]'` mapped characters literally and rejected valid tags in bash:3.2; an equal-length explicit mapping (`', \t\n\r\v\f'` to seven newlines) works everywhere. (2) BusyBox `touch -t` normalizes impossible dates such as Feb 30 instead of failing, so date validation must be done in bash (Gregorian month lengths and leap years). (3) .NET `\s` also matches U+0085 and U+00A0, unlike POSIX `[:space:]` under LC_ALL=C, so a PowerShell twin can stop a secret value early and leak the rest; use explicit ASCII whitespace classes. (4) awk interval expressions are not portable; use `sed -E` or spelled-out repetition.

How detected: running the same evidence scripts on the host and inside `docker run bash:3.2` (BusyBox) and diffing, plus a byte-parity corpus between the bash and PowerShell twins including 0xA0/0x85, CRLF, lone CR and no-final-newline inputs.

Avoid it: for any twin or portability claim, diff host vs BusyBox output and bash vs pwsh output on an adversarial corpus before evaluation.
