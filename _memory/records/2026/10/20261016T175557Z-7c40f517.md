Pitfall: editing a golden-case `.prior` file without updating its hash in the case's prior manifest silently turns an upgrade test into a blocked-upgrade test.

What happened (agent-kit goal orchestration-evidence-collector): the plan replaced a stale caveat in every emit-golden fixture, including `cases/*/.cursor/skills/agent-kit-models.map.md.prior`. Those cases' `orchestration-kit.manifest.json.prior` record a sha256 per emitted file; on `--upgrade`, `emit.sh` (~2510–2531) treats a file whose bytes no longer match as user-modified and blocks it (exit 4). Because `emit-golden.sh --update` regenerates goldens from whatever the emitter does, the goldens would have recorded the blocked upgrade as expected and the suite would still pass.

How detected: the Phase 3 goal evaluator read the upgrade code path and the prior manifests before any task ran (upgrade-retain, error-upgrade-blocked, error-manifest-no-answers all list the models map).

Avoid it: when a fixture edit touches any `.prior` file, recompute that file's hash in the same case's manifest `.prior` (plain sha256 of the bytes, as `emit.sh` ~107–113 does), apply text edits to rendered markdown in its unescaped wrapped form, and add acceptance checks that `cases/*/emit.exit-code.golden` are unchanged (`git diff --exit-code`) and that upgrade-case stdout/stderr goldens show no new blocked or retained paths.
