Decision: kit evaluators stay read-only where the harness enforces it. They judge orchestrator-run verbatim evidence instead of running commands themselves.

The emitted Cursor evaluator, qa-evaluator and diagnostician agents carry `readonly: true` (`emit.sh`), so shell calls are refused. The evaluator body used to require "Execute before you score", which made every Cursor verdict formally invalid.

Resolution (agent-kit, unreleased):
- `templates/agents/evaluator.md` says that when the harness runs it read-only (shell refused), it uses orchestrator-supplied verbatim evidence: each acceptance criterion's command plus its output. It marks those items as orchestrator evidence in "What I verified", and treats a criterion with no evidence as an issue, never a pass.
- The feature skill's Phase 4 step 3 and Phase 5 always launch the evaluator. If the evaluator is read-only (`readonly` in the emitted agent file, or a refused shell), the orchestrator first spawns `terminal` for each acceptance-criterion command and attaches the output.
- qa-evaluator and diagnostician already had cannot-run fallbacks and were left unchanged.

Alternative rejected: dropping `readonly: true` from the Cursor evaluator. It would let evaluators mutate the tree they judge and break the "never fixes anything" stance.

Consequences:
- Evidence quality now depends on the orchestrator. Evidence must be complete before the evaluator spawns.
- The feature SKILL template has only 2 bytes of headroom under its 11264-byte guard after this edit.
