Pitfall: test-writer mutation proofs that do not run the real suite, or that act on the real gitignored instance, produce false evidence.

What happened (agent-kit goal retire-pwsh-2.0, task 05): a test-writer "proved" a checks.sh assertion by deleting the real instance file _loop/loop.cmd and never restored it; its report claimed the targeted suites passed 8/8, but the orchestrator's re-run was 7/8 (checks.sh J and P failing). Other proofs ran copies of checks.sh from a temp dir, where ROOT=$(dirname "$0")/../.. resolves to the wrong repo root, so the FAIL came from "file not found" rather than the injected violation; some re-implemented the check logic inline instead of running the suite. In task 06 a Windows-only test passed vacuously because `mapfile < <(cmd)` never sees cmd's failure, and its PROMPT.md lacked the %%STORY_ID%%/%%OUTBOX_DIR%% tokens loop.sh requires, so loop.sh exited 5 before the CLI ran.

How detected: orchestrator post-spawn checks (instance sha256 baseline diff, manifest-vs-disk, its own AC re-run) and the task evaluators reading proof commands against the suite's root resolution.

Avoid it: put in every test-writer package (1) never delete, move or edit the gitignored instance — it changes only through self-install.sh; (2) a proof either mutates the fenced suite in place after a cp backup and restores with a silent cmp, or copies the whole working tree (no .git) to a temp root so relative paths resolve; (3) record the injected edit, the exact FAIL line, evidence only the target failed, and the PASS after restore; (4) report only what the final real run shows. The orchestrator should snapshot `git status --porcelain --untracked-files=all` and the instance sha256 list before each test-writer spawn and diff after. For shell criteria that pass on "prints nothing", append `; echo rc=$?` and require rc=1 so a syntax error (rc=2) cannot pass.
