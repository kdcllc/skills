Decision: agent-kit Phase 4 ready groups run in the shared checkout with a group repository check, not in per-member git worktrees.

Alternatives considered: (a) strictly sequential Phase 4 (previous behavior); (b) per-member git worktrees with diff merging (strongest isolation; Cursor documents isolated project copies, the loop already uses LOOP_WORKTREE); (c) shared checkout with rules — chosen.

Rationale: write fences already make tracked-file writes disjoint, so a shared checkout plus a group repository check (baseline HEAD/branch/config + `git status --porcelain --untracked-files=all` snapshot; every new path mapped to exactly one member's fence and cross-checked against member reports) catches tracked-file violations without merge machinery. The known gap — shared unfenced state (build outputs, caches, test databases, ports, a generated instance, regenerated fixtures) — is handled by running such tasks alone, plus no orchestrator write to shared state while members are in flight (ledger writes exempt). The test-ladder closer task also runs alone and last.

Consequences: default on (`parallel: false` opts out; up to 3 members, matching the loop's LOOP_SLOTS clamp); evaluators run in parallel only when read-only and no writer is in flight; fix cycles start only after in-flight evaluators return; any member escalation pauses the goal; a concurrency-related spawn error falls back to sequential for the rest of the goal (self-contained rule — installs carry no harness matrix). Harness matrix: Claude Code and Cursor document concurrent subagents (Claude Code default limit 20); Copilot and Codex unverified. Worktree isolation remains the steelman alternative if shared-state collisions appear in practice.
