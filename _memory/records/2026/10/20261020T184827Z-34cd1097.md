Pitfall (goal rule-file-feedback, 2026-10-20): text-shape criteria that look strict can be blind to the exact edit they guard.

1. Diff detectors that skip headers with `grep -E '^-[^-]'` (or `^[-+][^-+]`) also skip every removed/added Markdown bullet, because a removed bullet diffs as `-- **Rule.** …`. Use `grep -E '^-' | grep -vE '^--- (a/|/dev/null)'` (and the `+++ (b/|/dev/null)` twin) and prove it with a removed-bullet true positive.
2. A rewrap task checked by "no line > N chars" + "whitespace-collapsed text identical" passes a greedy fmt/fold wrap that splits a backtick span (`` `Rule files to cite` `` → `` `Rule`` / ``files to cite` ``), which then breaks downstream phrase guards. Add an odd-backtick-per-line check and a whole-span grep.
3. Criteria that pin line numbers (`NR>=309`, a range ending at a line's first word) become unsatisfiable when the task itself rewraps those lines — anchor ranges on stable text before and after the edited block.
4. "prints nothing" for a diff against a /tmp snapshot passes if the snapshot vanished (diff exits 2, stderr only) — require exit 0 too.
