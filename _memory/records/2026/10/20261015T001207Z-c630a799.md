## Decision

The kit keeps all orchestration state under `_memory/`. The top-level `_goals/` and `_research/` folders are retired.

- **In-flight work** lives in gitignored scratch:
  - `_memory/work/goals/<goal>/` holds goal.md, task files, orchestration-log.md, spawns/, evidence/ and memory-drafts/.
  - `_memory/work/research/` holds prompts/, `<topic>/report.md`, recalled-memory.md and the `ingested` marker.
- **Autonomous-loop state** lives in tracked `_memory/loop/`: backlog.md (the emit seed), LEARNINGS.md and ESCALATIONS.md (`merge=union`) and archive/. `breaker-state.json` is gitignored.
- **Finished knowledge** still goes into immutable `_memory/records/` (and `quarantine/`). Only those trees are scanned by `check`, `index` and `search`.

## Why

The user wanted one kit-owned tree instead of three top-level folders. Loop state stays tracked because `LOOP_WORKTREE=1` worktrees need a tracked backlog and the ledgers are shared through `merge=union`. Goal and research scratch is not shared and stays ignored.

## Rejected alternatives

- Tracking all of `_memory/work/`: it would commit spawn context and evidence noise.
- Writing every goal, task and log step as an immutable record: active work needs mutable files and write-set fences.
- A standalone `migrate-layout` subcommand: the user chose "upgrade moves".

## Consequences

- Emit migrates legacy folders whenever it finds them, on a fresh install or an upgrade.
  - It uses `git mv` when files are tracked, then untracks the goal and research folders. Loop files stay tracked.
  - It removes the retired `_goals/...` git lines by exact match and leaves every other byte alone.
  - `--dry-run` lists `migrate` actions. A conflict blocks with exit 4. `--force` keeps both copies.
  - `--root ""` is now rejected with exit 2.
- The loop story rule forbids only `_memory/records/` and `_memory/quarantine/` in `writes:`.
- Phase 6 / align-docs treats the whole `_memory/` tree as read-only.
- Teammates must upgrade (move) before pulling a commit that untracks goal folders. `LOOP_WORKTREE=1` users must commit the staged `_memory/loop/` move.
