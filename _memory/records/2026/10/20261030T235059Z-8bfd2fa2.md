Pitfall: a task's acceptance criteria ran only its own suites, so a repo-wide guard went red unseen.

What went wrong: in release-backlog, task 02 added a user-specified summary hint to templates/tools/hook-log.sh that contained the literal path `.claude/settings.json`. tests/agent-kit/templates/cursor-isolation.sh requires zero `.claude` occurrences anywhere under skills/agent-kit/templates/. Task 02's criteria ran hook-log.sh and kit-guard.sh only, so the task passed evaluation and was committed while cursor-isolation was red.

How it was detected: three tasks later, task 07's criteria happened to include cursor-isolation.sh, and its implementer reported the failure as outside its write fence. A corrective task (02a) reworded the hint without the path.

How to avoid it: any task that edits files under skills/agent-kit/templates/ (or another tree that a repo-wide guard scans) must list those tree-scanning guards in its acceptance criteria, not just its own suite. The tree-scanning guards are cursor-isolation, template-currency, skill-slimming and checks.sh. When a requirement quotes exact user-approved text, grep the guards for forbidden substrings (`.claude`, `judg`, model IDs, sibling names) before planning.
