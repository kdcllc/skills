Decision: fixture-root guards and removal of cd "$REPO_ROOT" apply only to agent-kit test suites that write (create fixtures, run emit, or run git against a root). Read-only suites keep cd "$REPO_ROOT". This is the user's choice in goal safety-hardening.

Alternatives considered: guard every suite and remove every cd, which touches many suites for little gain; or guard only the emitter, which leaves the test-side failure mode open.

Rationale: the incident class is an empty or wrong root reaching a write. Read-only suites cannot damage the repo through the cwd.

Consequences and known follow-ups (from the final audit):
1. tests/agent-kit/templates/windows-launcher.sh was classed as read-only but creates fixtures under RUN_TMP (mktemp without an empty check or assert) and emits through emit-cache while cd'd to the repo root. Its writes are absolute paths today, so it is safe now but unguarded. Next hardening pass: give it FIXTURE_TMPDIR and assert_fixture_root.
2. The emit-cache cache-dir rule accepts "/" or an ancestor of the repo; only keyed entry-*/staging-* subpaths are written. A future pass could reject ancestors.
3. The log-spawn empty --root mutation proof runs a mutant that resolves against "/"; harmless unless /_memory/work/goals/<goal> exists.
4. Remaining cd "$REPO_ROOT" sites: cursor-isolation, windows-launcher, invocation-flags, skill-slimming, escalation-ladder, model-enforcement, forge-adapter, template-currency, and run-all.sh itself.
