## Decision

The agent-kit loop guards added after 1.1.2 (run ledger and summary, `LOOP_ITER_TIMEOUT`, token/USD budgets, `LOOP_TAMPER_CHECK`, `--lint`) exist only in the bash driver `loop.sh`. `loop.ps1` and `breaker.ps1` are frozen at agent-kit 1.1.2 behavior: only their header comments changed, replacing the old "behaviorally identical twin; any divergence is a bug" contract with a frozen-twin statement. Windows users get the new guards by running `_loop/loop.sh` under Git Bash. Every new limit is opt-in (off when unset) except the ledger (on by default, `LOOP_LEDGER=off` disables) and the tamper check (default `warn`, report-only). Tamper `fail` is allowed only with `LOOP_WORKTREE=1`, because quarantining a branch is the only non-destructive response; on the main tree it exits 5 at startup.

## Alternatives considered

- Keep the twins in parity: doubles the work for every guard and the PowerShell harness coverage is thin.
- Retire loop.ps1 behind the Windows launcher: out of scope for this goal.
- Limits on by default: risks stopping existing loops unexpectedly; the user chose opt-in.
- Tamper fail on the main tree: there is no safe disposal for a shared tree (no reset allowed), so it was refused.

## Rationale

The research found the loop's main gaps were stop conditions and retry evidence, not platform reach. Freezing the twin keeps the bash driver moving without leaving a parity promise that would be false.

## Consequences

Docs, ORCHESTRATION.md, the auto-loop skill and the CHANGELOG mark every new knob bash-only. breaker.sh (not edited by this goal) still carries the old "behaviorally identical" sentence, now inconsistent with breaker.ps1; recorded as a follow-up.
