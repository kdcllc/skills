Pitfall (goal feature-skill-size, 2026-10-20): proving a text move and its guard retargeting is easy to get subtly wrong.

1. Word-level diff runs are a weak loss detector: words shared with the replacement pointer show as context and are never checked, short fragments match anything, and a reworded line can pass without its new text existing. Check whole old paragraph spans (from `git show BASE:file`, indent stripped, whitespace normalized) as substrings of the new home, and require every ledger "new" text to be present.
2. Mutation-proof needles taken from a report label match the PASS line too (labels print on PASS and FAIL); match the exact `FAIL: <label>` prefix (plus detail text when several checks share a label).
3. When retargeting a guard, do not change neighbouring anchors that still match — a "harmless" anchor swap removed the only pin on another file's tree entry.
4. A regex alternation in a guard (`a|b`) can hide that one branch was the real pin; moving text that satisfied branch `a` leaves the check passing on `b`. Removal sweeps (delete text in a scratch repo, diff suite output vs a control) do not catch this — read alternations in every guard that greps the moved file.
5. Read-only evaluators occasionally fail to read existing files; verify "missing artifact" claims with `ls` before acting.
