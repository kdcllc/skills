Pitfall: targeted suite runs during task evaluation miss repo-wide guards and go stale against the gitignored instance; only the full `run-all.sh` before the final audit catches them.

What happened (agent-kit goal memory-prune): every task passed its targeted checks (memory-prune, memory-wiring, skill-slimming, cursor-isolation, emit-golden), yet the first full `bash tests/agent-kit/run-all.sh` failed `tests/agent-kit/templates/legacy-paths.sh`. New README prose for `prune` contained the literal retired token `_goals/…`, which that guard forbids in kit sources outside its allow-list. Separately, `tests/agent-kit/templates/memory.sh` check `(t) instance byte-identity` failed during audit evidence gathering because the gitignored `_kit/memory.sh` came from a self-install that ran before the last template fix.

How detected: the final auditor refused APPROVED without a full rung-3 run after the version bump; the run exposed the legacy-paths hit. The stale instance showed up as a single FAIL in a targeted run.

How to avoid:
- When new template prose mentions legacy layouts, describe them in words ("the legacy top-level goal path") rather than writing `_goals/` or `_research/`, or add an allow-list line in the same change.
- Re-run `bash scripts/agent-kit/self-install.sh` after every template edit before running suites that compare the instance with templates.
- Run the full `validate-skills.sh && run-all.sh` (via a terminal spawn) before the Phase 5 audit, not only after it.
