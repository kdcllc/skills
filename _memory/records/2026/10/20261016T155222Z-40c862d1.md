Decision: when agent-kit cannot spawn subagents, the orchestrator self-performs roles and advances self-evaluated gates after telling the user, instead of deferring gates until an independent evaluator is available.

Alternatives considered: (a) refuse — stop and escalate whenever no spawn tool exists; (b) defer — do implementer work but mark every gate "pending independent evaluation" and refuse Phase 5 / commit until a spawning session re-runs the evaluations (keeps "never complete without evaluator PASS" literally true); (c) chosen — self-perform with disclosure.

Rationale: the user chose (c) in Phase 1. Disclosure is the compensating control: verdict-role outcomes are logged `--model-reported self` + `--note "self-evaluation, not independent"` (worker roles `--note "self-performed (degraded mode)"`), every self-evaluated gate is told to the user, listed in the end-of-goal final report, and in a `## Self-evaluated gates` section of the PR draft (ship-pr scans every goal's orchestration log on the branch). Verdict roles are never self-performed when a spawn tool exists; transient failures keep the 3-retry rule; a rejected model argument is a separate case (inherit re-spawn, persisting for the goal).

Consequences: independence is lost in Case 2 and model-tier guarantees in Case 1; unattended runs (cloud, loop) have only the PR draft and final report as human checkpoints; goals with `pull_request: false` rely on the final report alone. The iron-rule pointer in the feature skill relaxes only the product-code, model-pin, and terminal rules — re-evaluation and cycle caps still hold.
