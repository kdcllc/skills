Open follow-ups after goal memory-store-followups (agent-kit memory store, unreleased). None blocks; the final audit was APPROVED with notes.

Carried and accepted by the final audit:
1. Long unwrapped lines in the feature SKILL template (Phase 4 step 3, Phase 5) and the memory-capture SKILL scope gate. The file already had 7 lines over 120 characters. A space-to-newline reflow is byte-neutral for the size guard.
2. The feature SKILL template says `readonly`, not `readonly: true`. It has 2 bytes of headroom under the 11264-byte skill-slimming guard, so the next edit must trim first.
3. The `memory-wiring.sh` leak counter counts every `memory-wiring.*` root in TMPDIR, so concurrent copies of the suite fail it. A per-run prefix would fix this.
4. The `memory-capture.sh` 6-digit `--idle-hours` check uses substring negation. The exit code carries the proof.
5. The supersede rule looks only at the latest `.distilled` row. In the sequence distill → grow → skip → grow → distill, the first record is never superseded.
6. ORCHESTRATION's light rubric ("requirements walk + targeted tests") could gain a read-only-harness clause.

Still open from earlier memory follow-ups (out of scope here):
- backfill performance (subprocess count per record, line and goal);
- capture hooks;
- `head -c` portability note;
- loop step 3b `check`;
- the approximate one-day fallback overlap window.
