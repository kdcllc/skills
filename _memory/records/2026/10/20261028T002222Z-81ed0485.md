## Question

Should agent-kit adopt five gate patterns from a sibling orchestration system ("Project A")? They are: a blind goal-level contract with a consumer trace; cite-or-backlog with "the first cycle sets the blocking list" and "a PASS is final"; a fixed issue-line format with progress-based loop termination (no cycle cap); classifying quality-check failures; and Cursor hook field notes. The kit's settled decisions shaped the question: per-task contracts were removed in v0.23.0, strict mode and list diffing were rejected on 2026-10-23, the 3-cycle cap plus ladder stays, and the kit installs no hooks by default.

## Load-bearing findings

- Missed consumers and call sites are a common failure. Call-site recall was about 0.66 with both grep and LSP (arXiv:2608.13568, spot-checked), so thoroughness, not tooling, is the bottleneck.
- No evidence shows that a blind criteria writer beats a planner-written trace.
- LLM judges flip 7–17% of verdicts on identical replications (arXiv:2610.12083, spot-checked). That supports "a PASS is final" and demoting late findings outside changed code to a backlog.
- Repair gains concentrate in rounds 1–4. The progress-stopping paper (arXiv:2607.17641, spot-checked) shows degradation only in a stress setting, and its method still keeps a round budget. So keep the cap and add a progress signal inside it.
- Cursor staff confirmed on 2026-10-12 (forum thread 174283) that a deny's `agent_message` never reaches the agent; put agent-facing text in `user_message`.
- Cursor docs say hooks do not run in a cloud agent's read-only early turns.
- Cursor and Copilot both run repository `.claude/settings.json` hooks, so a hook there runs in three harnesses. Cursor sets no loop limit for Claude-format stop hooks.

## Recommended direction (pending user decisions)

- Item 1: a planner-written `## Consumers` section in goal.md, built from literal rg searches run through terminal with verbatim hit lists, checked by goal-criteria and the Phase 5 audit. No blind spawn except possibly for bypass-class goals.
- Item 2: cite-or-backlog with a goal backlog file and a PR-body backlog section. After cycle 1, block on `[new]` findings only in changed code or a severe list (the bypass classes plus authorization bypass, cross-tenant access, secret exposure, wrong-target mutation, data loss, hangs). This revises the 2026-10-23 decision and needs a superseding decision record.
- Item 3: normalized issue keys as instrumentation. The same key in two consecutive cycles is an early exit into the ladder; the cap stays. Never use fuzzy or embedding matching as a gate.
- Item 4: a dirty-file snapshot at start, one flake rerun, and a base-branch run of the failing check. Report and backlog pre-existing failures; backlog-only in loop mode.
- Item 5: Cursor hook rows in the harness matrix, added only when implemented. Hooks stay opt-in telemetry.

## Open questions

The recall cost of restricting late findings; evaluator wording fidelity across fresh calls; blind versus planner trace catch rates; Cursor desktop hook behavior (re-check by 2027-01-27); and the lack of any vendor policy on pre-existing failures.
