## Question

How should the kit give cross-session, cross-machine, team-shareable recall when harness-native memory is not cross-harness and the kit repo keeps `_goals/` / `_research/` gitignored on the self-install instance?

## Load-bearing findings

- Harness-native memory (Claude auto memory, Copilot Memory, Codex memories, Cursor stores) cannot serve as the canonical store; Copilot Memory expires after 28 days unused; Cursor agent stores mount on tmpfs locally (observed 2026-10-08).
- Kit-owned store: git-tracked `_memory/` with one immutable markdown record per file (YAML frontmatter: id, kind, title, date, source, commit, tags, supersedes, sha256); add-only paths; supersession via new records, not edits; `.index/` and `raw/` gitignored.
- Sync is plain git pull/push; search is manifest + grep/rg with optional SQLite FTS5; qmd semantic search deferred.
- Only orchestrator reads (≤5 records, DATA fence, not instructions); only orchestrator or loop integrator writes; admission screen quarantines instruction-like bodies.
- Claude Code reads AGENTS.md only when no CLAUDE.md exists in cwd or above (v2.1.277+); kit installs use CLAUDE.md pointers. Subagents must not set Claude `memory:` frontmatter.

## Decisions taken

- Track `_memory/` on main in the kit repo; records self-sufficient because `_goals/` stays gitignored.
- v1: keyword search + optional FTS5; transcript capture via post-hoc scanners and session summaries, not hooks first.
- Tools emit as `_kit/memory.sh` / `.ps1` twins from setup templates, not under `scripts/`.
- Roadmap: Release A core → B wiring → C capture → D backfill.

## Open questions

- Cursor `cursor_agent_stores` persistence and semantics; MCP on custom subagents; Codex/Copilot export formats; mem0/Zep/Letta not evaluated; in-repo A/B on evaluator PASS rates with memory fence on/off.

## Where it shipped

Kit v0.30.0 (`memory-store-a-core`): record schema, `_kit/memory.*` twins, emitter wiring. Releases B–D remain planned per the doc roadmap.
