Decision: align-docs proves Phase 6 changed only docs by diffing two git tree-object snapshots of the working tree, not by a per-path hash list or `git status`.

Mechanism: before any doc edit, `PHASE6_INDEX="$(mktemp -d)/index"` and `PHASE6_TREE=$(GIT_INDEX_FILE="$PHASE6_INDEX" git read-tree HEAD && GIT_INDEX_FILE="$PHASE6_INDEX" git add -A && GIT_INDEX_FILE="$PHASE6_INDEX" git write-tree)`; later take a fresh snapshot the same way and run `git diff --name-status --no-renames "$PHASE6_TREE" <new tree>`. Record BASE_SHA and PHASE6_TREE outside the repository (shell variables may not persist between calls), never under _memory/.

Alternatives rejected: (1) `git status` docs-only check — fails whenever the feature's own code is uncommitted, which is the normal interactive /feature state; (2) a `git hash-object` list built from `git diff --stat` — --stat truncates long paths and prints renames as {a => b}, and a path that disappears from the re-listing (an executor reverted feature code to base, or deleted an untracked file) is never checked.

Consequences: renames, deletions, reverts to base, untracked files, and tracked files matching .gitignore are all caught; the real index is untouched and only loose objects are added under .git/. Only untracked gitignored paths stay outside the snapshot (same blind spot as git status). Seeding the temp index with `git read-tree HEAD` is required — an empty temp index skips tracked-but-ignored files. Phase 6.4's per-doc rule must allow docs already executed earlier in the run, since the snapshot is taken once.
