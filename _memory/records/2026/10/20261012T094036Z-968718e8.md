Pitfall: guard tests that forbid literals under `skills/agent-kit/templates/` constrain
user-facing template prose, not just code.

What happened: the emitted single-copy `_memory/README.md` was written to name the protocol
path for every harness folder. That broke two guards at once:
- `tests/agent-kit/templates/cursor-isolation.sh` check 4 rejects any `.claude/` substring
  anywhere under templates/;
- `tests/agent-kit/templates/memory.sh` case (q) rejects any `{{` token in the memory README,
  and case (t) requires the emitted copy to be byte-identical to the template.
A later review also found `.codex/` was simply false: Codex installs emit no kit skills tree.

How to avoid:
- Before writing template prose that names harness folders or tokens, grep `tests/agent-kit/`
  for guards scanning that path (cursor-isolation, memory.sh, checks.sh check E for
  `(claude|gpt|gemini)-[0-9a-z]` literals).
- For single-copy emitted docs, name paths as `<harness dir>/…` with examples that exist for
  every harness that receives the file (`.cursor/`, `.github/`), and state the Codex-only case
  explicitly.
- Run the full `tests/agent-kit/run-all.sh` before closing a task that edits templates; the
  regression surfaced only when a later task ran cursor-isolation.
