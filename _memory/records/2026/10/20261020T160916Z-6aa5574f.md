## Decision

Executable acceptance criteria (agent-kit goal-criteria + pre-flight check 1) require recorded evidence for every shell-command criterion in `_memory/work/goals/<goal>/criteria-evidence.md`, but true-negative/true-positive demonstrations only for **content-inspecting** checks (grep/rg/awk/sed/wc/diff/count assertions). Criteria that only run an existing tracked suite or check an exit code record a current-tree run, or `not runnable yet — created by task NN`. Before the code exists, TN/TP may be shown on a minimal scratch sample outside the repo. A criterion requiring writes outside the task's `writes` is an ownership gap for the orchestrator to re-plan, not a criteria defect.

## Alternatives considered

- TN/TP for every command criterion (rejected at Phase 3: impractical for "suite exits 0", likely to produce fabricated boilerplate).
- A tracked helper tool that records cmd + TN + TP (Phase 1 chose prose rules, no new `_kit/` tool).
- Routing fence-breaching criteria to arbitration as criteria-defect (rejected: task-criteria already routes out-of-fence needs to orchestrator re-planning; one route only).

## Rationale

The source run lost whole revision rounds to vacuous greps, blind fence checks, and mutually unsatisfiable criteria; running criteria with both directions caught them when done ad hoc. Scoping the demand to checks that inspect content keeps the rule honest and cheap.

## Consequences

- Vacuous or blind criteria map to the arbitration rubric's **untestable** type; mutually unsatisfiable pairs map to **contradiction**.
- Pre-flight may now write goal artifacts (criteria-evidence.md, reference-sweep.md) and scratch samples; amendments re-run checks 1, 2 and 5.
- Prose gates still depend on orchestrator diligence (accepted risk).
