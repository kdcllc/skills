1. **Most "sessions" are subagents.** Of 55 top-level Cursor transcripts, 27 were subagent runs: evidence and terminal runs, fix cycles, re-checks. Release C needs a classifier, e.g. on the first user query ("Your full context package…", "Read <repo>/_goals/…", "Re-check request"), before it distills anything.
2. **Skip the live session.** The in-progress chat produced an incomplete summary. Capture should only distill sessions that have been idle for N hours, or that are explicitly closed.
3. **Off-topic sessions exist.** Two sessions in the repo's transcript folder had nothing to do with the repo. Capture needs a scope gate, so a human or the user confirms before anything enters shared memory.
4. **Distillers misattribute decisions.** The most common error was crediting the user with assistant recommendations or orchestrator defaults. A rewording pass even introduced a new false approval. The distill prompt should require a quoted user turn for every "User chose/approved" claim.
5. **Tag drift.** One batch used space-separated tags, and several exceeded 6 tags or used goal tags from the wrong period. The writer should normalize separators. Distillers need the list of goal folders with their date ranges.
6. **Corrections need tooling.** Records are immutable, so a fix meant deleting files and re-running the writer. Deleting by timestamp prefix removed unrelated records that shared the timestamp; dedupe restored them. Release C, or a small follow-up, should add `memory rm <full-id>` for uncommitted records, or a `supersedes`-based correction.
7. **Privacy grep must include the repository owner name.** An earlier PASS missed an owner/repo slug in a back-fill record.
8. **Cost.** 6 distill spawns over about 2.3 MB of compact transcript, plus 2 fix cycles and 3 evaluator passes, produced 24 useful records. That is reasonable as a one-off, but for routine capture, incremental per-session distillation is preferable to batch.
