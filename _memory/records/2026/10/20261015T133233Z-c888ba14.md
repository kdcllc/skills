Goal safety-hardening: shipped on branch feature/safety-hardening (agent-kit, Unreleased). It closes the open items of pitfall 20261015T004721Z-f50ffadd, where an empty root variable made a tool act on the current directory, which was the real repo.

What changed:
- _kit/log-spawn.sh: an explicitly empty --root exits 2 with usage. Before, it resolved paths against "/". This matches bin/emit.sh --root "" from the memory-work-layout goal.
- Test suites that write: emit-golden, emit-portability, memory-capture, memory-release-c, emit-cache (plus templates/memory.sh and lib/selftest.sh) call assert_fixture_root (tests/agent-kit/lib/fixture-root.sh, fail-closed) before every emit, git -C or --root write. The emit suites no longer cd to the repo root. emit-cache has its own rule: the cache directory must be non-empty, absolute, existing and outside the repo, and it is never created by mkdir -p.
- ORCHESTRATION.md gained "Repository safety" (Core Concepts): back up before goals that move or delete user files; after every subagent compare HEAD, branch, git config --local user entries and git status against the write fence, and stop and restore on anything unexpected; fixtures stay under a private temp dir and empty path arguments are rejected. The feature skill points to it.

Key decisions: user chose cd_scope = writers (read-only suites keep cd "$REPO_ROOT") and orch_ref (rule text lives in ORCHESTRATION, the feature skill only points to it, because the feature SKILL byte budget is 11264 and is now at 11260).
