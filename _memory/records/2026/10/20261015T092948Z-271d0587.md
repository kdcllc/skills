Decision: the Docker bash:3.2 emit-golden check in tests/agent-kit/templates/emit-portability.sh is opt-in with AGENT_KIT_DOCKER=1, and CI runs it.

- Unset, empty or 0: SKIP with "set AGENT_KIT_DOCKER=1 to run"; no docker command runs at all.
- 1: run it; FAIL (not SKIP) when docker is not on PATH or the bash:3.2 image is missing, so CI cannot pass without running it.
- Any other value: FAIL ("must be 0 or 1").
- .github/workflows/agent-kit.yml pulls bash:3.2 before the suite step and sets AGENT_KIT_DOCKER: '1' on it. tests/agent-kit/run-all.sh usage lists the variable.

Why: the leg ran a network apk add git plus the whole emit-golden suite inside the container on every local run (a large share of emit-portability's 211 s), while ubuntu-latest CI had no bash:3.2 image and printed a SKIP, so the Bash 3.2 check effectively ran nowhere.

Alternatives rejected: keep it on by default with a pre-built image (still slow locally, still skipped in CI); opt-in with no CI change (the check would never run).

Consequences: local Bash 3.2 regressions surface in CI, not on a default local run; maintainers run AGENT_KIT_DOCKER=1 before touching Bash 3.2-sensitive code. CI depends on pulling bash:3.2 from Docker Hub.
