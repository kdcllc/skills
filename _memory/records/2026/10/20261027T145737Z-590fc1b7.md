Decision: retire the last PowerShell 7 scripts (loop.ps1, breaker.ps1, memory.ps1) in agent-kit 2.0.0 and make the loop Bash-only behind a `_loop\loop.cmd` Git Bash launcher, the same byte-copied launcher already used for bin\emit.cmd, _kit\memory.cmd and _kit\log-spawn.cmd.

Alternatives considered: keep the frozen loop.ps1 twin (the 1.1.2 freeze); ship 1.2.0 with a deprecation stub first; emit a few-line loop.ps1 tombstone/wrapper that forwards to loop.cmd so existing `pwsh _loop/loop.ps1` scripts keep working. The user chose "delete now" and declined the wrapper.

Rationale: the twins required pwsh 7, which fresh Windows does not ship; the freeze left bash-only caveats spread across the kit and a false parity promise; Git Bash is already required by the other launchers and by Claude Code on Windows. Bumped to 2.0.0 because removing a supported entrypoint is breaking.

Consequences: pwsh-only callers break on upgrade and must switch to `_loop\loop.cmd` (cmd or any PowerShell, Git for Windows required) or `_loop/loop.sh` in Git Bash; unmodified .ps1 files are pruned on upgrade, modified ones remain with a warning; existing `*.ps1 text eol=lf` lines in user .gitattributes are left alone. Two Windows behaviors stay documented as unverified known limitations until the non-blocking windows-latest CI job proves them (native-child survival after a slot kill; `.cmd` shim resolution, whose suffix workaround truncates the multi-line prompt through cmd.exe). Supersedes the 2026-08-18 decision to keep a PowerShell loop.ps1 twin and the 2026-10-23 decision that froze loop.ps1/breaker.ps1 at 1.1.2 with bash-only guards.
