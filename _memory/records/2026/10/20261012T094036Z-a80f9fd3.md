Decision: the loop driver's integrator commits the memory records it adds from slot
proposals, using a path-limited commit (`git add -- <paths>` then
`git commit -m "chore(memory): <story-id> records" -- <paths>`), instead of leaving them
uncommitted in the main tree like `_goals/LEARNINGS.md` appends.

Context: `_memory/records/` and `_memory/quarantine/` are protected paths. At the default
`LOOP_WORKTREE=0` the next dispatched slot runs in the same tree; if it ran `git add -A`, it
would sweep untracked records into its commit, and circuit breaker CB0 would then
`git reset --hard` that slot's range, deleting the records and stopping the run (exit 4).

Consequences:
- Step 3b runs at the end of the reap, after CB0 and disposal, so a CB0-tripping slot's
  proposals are never integrated.
- The commit is skipped when nothing was added or quarantined (a bare `git commit --` would
  commit whatever is staged).
- Commit paths come only from the tool's `memory: added` / `memory: quarantined` lines.
- If the commit fails (hooks, signing, no git identity) the driver prints
  `!!! memory records left uncommitted: git add|commit failed (exit N)` and the sweep hazard
  returns — keep a working git identity.

Rejected alternatives: a separate admission-only deny list for `_memory/` (keeps CB0 lists
unchanged but leaves records uncommitted); relying on prompt text alone ("never git add -A").
