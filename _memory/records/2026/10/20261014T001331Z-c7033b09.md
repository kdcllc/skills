Decision: memory back-fill is deterministic and driven by explicit closed signals, not by an LLM distilling old work.

`memory.sh backfill` extracts fixed sections from files that already exist: the goal's Problem Statement, success criteria and final Phase 5 verdict; a research report's `## Summary of Findings`; and the whole escalation entry, including its resolved decision. It writes them through `add` with ids derived from source timestamps. A source counts as closed only through signals that are written down. Goals need a logged Phase 5 APPROVED outcome or note, or `--only`. Research needs `--only` (legacy topics) and is skipped once it has an `ingested` marker. Escalations need a `resolved:` line in the entry. Signals the kit writes from now on (the ARCHIVED note and the ingested marker) mark a source as already archived, so back-fill only picks up legacy work.

Alternatives rejected:
- An LLM-written summary per goal: not reproducible, expensive across many goals, and needs an evaluator gate per record.
- Treating every goal folder or research report as closed: would import abandoned or open work.
- A separate closed-state file per goal: one more artifact to keep in sync; the orchestration log already records the verdict.

Consequences:
- Record bodies are terse.
- `--plan` cannot see that escalations were already applied; only `--apply` reports them as duplicates.
- Back-fill is bash-only (Windows runs it through `_kit\memory.cmd`).
- Opting legacy research in is a human choice made with `--only`.
