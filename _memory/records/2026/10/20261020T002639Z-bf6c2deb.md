## Decision

bin/emit.sh blocks (exit 4, --force overrides) every emit-set path that already exists on disk with different bytes and has no entry in the previous manifest's files map — including first installs where no manifest exists. Paths that do have a previous-manifest entry keep the old rule (block only when disk differs from the recorded hash). The new class gets its own stderr line, "emit: blocked <path> (exists; not written by a previous emit)"; dry-run action lines stay "blocked <path>" for both classes. .codex/config.toml is the only exemption, because put_optional_kit_files puts it into the emit set as the user's existing bytes plus appended kit agent tables; .claude/settings.json enters the emit set only when absent, so it needs no exemption.

## Alternatives considered

- Write anyway but warn and back up the original (rejected by the user: silent-ish data movement).
- Never write and keep the user's file (rejected: half-installed kit with no clear next step).
- Write the kit file beside it (e.g. <path>.kit-new) and exit 0 (evaluator steelman; rejected: leaves no manifest entry and an incoherent install).
- Block only git-tracked files (rejected: untracked user files are just as user-owned).

## Rationale

Verified before the change: a project's own .claude/agents/evaluator.md was planned as "write" with exit 0 on first install — silent data loss. Reusing the existing exit-4 / --force contract keeps one mental model for users and tests.

## Consequences

- An install whose manifest was lost while emitted files remain is mass-blocked on re-emit until the user reviews and passes --force (documented in the changelog upgrade notes).
- In this repo the manifest is gitignored but _memory/README.md is tracked, so a fresh-clone self-install now exits 4 if that tracked file drifted from its template — effectively drift detection.
- Help/usage text in emit.sh, bin/README.md, SKILL.md Step 5/Upgrading, and self-install.sh --force-emit all describe both classes.
