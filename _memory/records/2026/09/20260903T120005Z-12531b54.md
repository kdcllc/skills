## Problem

`est_tokens = (context_chars + report_chars)/4` measured only orchestrator I/O with a subagent, not files read or command output the worker consumed—so tier and eval-depth decisions lacked an honest spend signal.

## Outcome

Shipped **kit v0.26.0** (commit `d65d7b1`, single release commit after frozen no-per-task commit discipline). Renamed the ledger field to **`io_est_tokens`**, added a mandatory **`### Footprint`** block on all six agent reports, extended `log-spawn outcome` with `work_read_chars` / `work_est_tokens`, and taught loop drivers optional real CLI usage capture via `LOOP_USAGE_FORMAT`. Docs, harness matrix row, instance re-emit, and tests updated.

## Key decisions

- Subagents self-report `files_read` and `commands_run`; only the `files_read: N (~C chars)` line is parsed (digit-only C); missing Footprint yields `n/a` on OUTCOME, not a ledger error.
- Running totals split: `running io` and `running work`.
- Loop **silent-none**: when `LOOP_USAGE_FORMAT` is unset and `auto` resolves to `none`, drivers emit no new stdout (existing harness behavior preserved).

## Pitfalls / lessons

- Goal evaluation needed three cycles to freeze codex JSONL shape, basename auto-detection, and task-level diff base `d06e9e5`.
- Post-audit implementer used `~6,000 chars` in Footprint—parser requires digits only; orchestrator overrode with `--work-chars`.
