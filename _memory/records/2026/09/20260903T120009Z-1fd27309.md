## Decision

`skills/setup/bin/emit.sh` requires **`jq` on PATH** and exits 2 with a message naming `emit.ps1` when jq is missing. `emit.ps1` parses nested JSON answers with PowerShell built-ins only.

## Why

Nested JSON answers with multi-line bootstrap texts are not safely parseable in pure Bash. jq is a single static binary already optional elsewhere in the kit; scoped deviation from “no new dependency” applies only to the bash twin.

## Rejected alternatives

- Pure-bash JSON parsing (rejected as unsafe for bootstrap multiline strings).
- Requiring jq for both twins (pwsh environments may lack jq).

## Consequences

CI and Linux dogfood typically use `emit.sh`; Windows-oriented flows can standardize on `emit.ps1`. Setup SKILL.md Step 5 runs emit inline (one-line stdout); terminal-spawn rule does not apply.
