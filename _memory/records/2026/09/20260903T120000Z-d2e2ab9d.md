## Problem

Orchestration logs showed most worker spawns ran on the frontier model, evaluators treated minor wording issues as blocking fixes, the continuation ladder consumed many frontier spawns before escalation, and Phase 6 doc sweeps touched every markdown surface per feature. Release A addressed this with template and prose changes only—no new tooling.

## Outcome

Shipped **kit v0.24.0** (commit `9aa98ad` on branch `feat/token-efficiency-roadmap`, later merged via PR #5 as `490e697`). Eight tasks updated canonical agents, criteria, feature skill, loop templates, align-docs skill, root docs, instance re-emit, and tests. Phase 6 and Phase 7 were skipped per goal (`align_docs: false`, `pull_request: false`).

## Key decisions

- Context packages require a `## Model` section; orchestrator passes an explicit model on every spawn; `model: inherit` in logs is disallowed unless the model-map row is deliberately unpinned.
- Every agent report starts with `**Model (self-reported)**: …`.
- New evaluator verdict **PASS (with notes)** when all issues are `minor`; **NEEDS FIXES** requires at least one `major` or `blocker`.
- `eval_depth` defaults to `light`; `full` is required for contract/scaffold tasks, tasks with interface consumers, and tasks writing agents, criteria, loop drivers, or shared infrastructure.
- `goal.md` gains `phases.ladder: escalate|auto` (default `escalate`); loop-created goals use `auto`.
- Phase 1 default for Phase 6 doc alignment flips to no; `align_docs: false` in goal templates; root `ORCHESTRATION.md` shrinks to a short pointer.
- Feature skill byte budget raised to 10240 bytes; version pins in tests read `skills/setup/VERSION` dynamically.

## Pitfalls / lessons

- The narrowed model-map rule (“prompts are executable → frontier”) bound the goal until task 01 landed—early spawns still used the old repo-wide frontier rule.
- Fix cycles on tasks 03, 07, and 08 were needed for log-path anchors, stale compiler copies, and vacuous version-pin tests.
