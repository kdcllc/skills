## Problem

`/setup` offered skills.sh skills only on the greenfield accept path and only by stack name. Existing projects got no suggestions, and greenfield ignored inspection signals (web UI, pytest, Dockerfile, etc.).

## Outcome

Shipped **kit v0.28.0** (commit `9890c2c`, PR #6). Added **Step 2b — Skill suggestions** to `skills/setup/SKILL.md` for every interactive setup (greenfield accept/decline and non-sparse), embedding the find-skills workflow inline without vendoring that skill. Version, README, CHANGELOG, getting-started, loop-harness assertions 125–135, and instance VERSION copies updated. Phase 6 doc audit APPROVED after one remediation cycle. A Copilot emit regression (missing `.github/skills/feature/SKILL.md`) was fixed on the feature branch before merge.

## Key decisions

- Seven frozen inspection signals map to skills.sh queries; cap 8 candidates total, 3 per signal, 1000+ install floor.
- Installed skills recorded via existing bootstrap ids `domain-skill-rows` and `layer-skill-map` in Step 4—no new template tokens or manifest keys.
- Script-only `emit.sh --upgrade` never runs Step 2b.
