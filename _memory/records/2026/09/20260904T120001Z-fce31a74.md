## Decision

Step 2b installs project-local skills with `npx skills add … --skill … -y` (never `-g`). Step 4 fills existing bootstrap answer keys **`domain-skill-rows`** (ORCHESTRATION.md skills table) and **`layer-skill-map`** (feature skill routing). No new template hooks, tokens, flags, or manifest keys; canonical templates and `bootstrap-ids.md` stay untouched.

## Why

Users need orchestrator-visible skill routing without expanding the emit contract or re-running emitter work for a setup-only UX feature.

## Rejected alternatives

- New dedicated bootstrap ids or manifest fields for third-party skills.
- Vendoring find-skills or auto-installing without user pick.

## Consequences

Emit and bin scripts unchanged in v0.28.0. Only skills actually installed count toward bootstrap text; fail-open printed commands do not. Upgrading via emit alone skips skill discovery entirely.
