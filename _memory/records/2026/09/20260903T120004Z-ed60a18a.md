## Decision

All orchestration-log append operations use `_kit/log-spawn.sh` / `_kit/log-spawn.ps1` (`spawn`, `outcome`, `note`). The scripts are append-only, compute byte lengths and `est_tokens` deterministically, and enforce ledger integrity (duplicate spawn NN or outcome without spawn → exit 3).

## Why

Removes frontier-model clerical work and arithmetic errors from the orchestrator. Dogfood for Release B proved the contract before Release C renamed metrics and added Footprint ingestion.

## Rejected alternatives

- Orchestrator continues hand-writing prose ledger blocks (Release A left this unchanged).
- Inline context/report in the log without artifact files (breaks Report integrity at scale).

## Consequences

Feature skill and ORCHESTRATION template document compact invocations with `--help` for full flags. Running `_kit/log-spawn.*` inline is exempt from the “spawn terminal for one-line commands” rule. Release C later extended `outcome` without changing the single-writer pattern.
